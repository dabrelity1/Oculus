- Oculus mixins must be queued through `OculusMixinLoader` as a Forge `IFMLLoadingPlugin` and MixinBooter `IEarlyMixinLoader`. Do not move registration back to `Oculus.onConstruction(...)`, `-Dmixin.configs`, `@MixinLoader`, or `ILateMixinLoader`; a local run proved that late registration crashes because `BlockStateContainer$StateImplementation` is already loaded before `BlockStateAmbientOcclusionMixin` prepares.

If startup with a valid enabled pack creates only `FixedFunctionWorldRenderingPipeline`, treat that as a regression.
- `run/config/oculus.properties` currently selects `ComplementaryReimagined_r5.6.1.zip` after the latest GUI/reload smoke. Change it deliberately if you need the extracted directory pack for a runtime test.
- `run/resourcepacks/Oculus-PBR-Validation` is a local LabPBR validation pack with dirt `_n` / `_s` companions, and `run/options.txt` currently enables it. It exists only to prove runtime PBR resource loading with `-Doculus.validation.pbrTextures=true`; the latest Xvfb smoke loaded the resource pack but did not record enough simple/atlas/custom resource PBR upload evidence to close PBR parity.
- `SimplePBRLoaderGlTest` is an opt-in Pbuffer harness for proving real simple `_n` / `_s` GL uploads. It is skipped unless `-Doculus.tests.pbrGl=true` is set; leave it disabled unless a known-good display or virtual display is intentionally being used for that proof.
- `OculusRuntimeValidation` is a dev-only, disabled-by-default helper for unattended client smokes. Launch `runClient` with `-Doculus.validation.autoJoinWorld="New World" -Doculus.validation.exitAfterWorldTicks=1200` to use the Forge 1.12 GUI world-load path without GUI automation and then shut down after enough in-world client ticks. Add `-Doculus.validation.pbrTextures=true` to log real simple PBR texture loads, atlas PBR uploads, and PBR holder texture IDs from the runtime load paths; it can also be used without auto-join during manual client runs. `build.gradle` forwards these three `oculus.validation.*` properties into the launched Minecraft JVM. When this hook is enabled, Relictium terrain override lookup/selection and shadow terrain layer requests are logged once per relevant pass/layer at the runtime call sites.
- `BufferFlipper` tracks the logical main/alternate read state. If a buffer is not flipped, current readers sample main and writers target alternate; if flipped, readers sample alternate and writers target main.
- `ProgramSet` constructs pack directives with the baseline supported render-target set, matching 1.16.5. That default set keeps `colortex0` available even when the shader pack does not explicitly declare render-target directives; the empty-framebuffer path depends on `colortex0`.
- The active 1.12 resize path recreates the `FramebufferManager` depth texture and then rebuilds `RenderTargets` in the same `ensureFramebufferDimensionsUpToDate()` call. Do not switch to in-place `RenderTargets.resize(...)` as the main path unless you also port the 1.16.5 depth reattachment/version logic.
- `FramebufferVersionMixin` mirrors the local 1.16.5 `Blaze3dRenderTargetExt` version bridge for 1.12 `Framebuffer.deleteFramebuffer()`. `FinalPassRenderer` uses the exposed color-buffer version plus `framebufferTexture` to refresh its `colorHolder` attachment when Minecraft recreates the main color buffer, even if a GL texture id is reused.
- Composite explicit pre-flips are applied before pass creation and do not count as "flipped at least once", matching the 1.16.5 comment around `deferred_pre` / `composite_pre` behavior.
- Composite/final sampler allocation reserves texture units `1` and `2`, matching the 1.16.5 postprocess builder path.
- Dynamic sampler allocation must respect `SamplerLimits`; do not reintroduce hard-coded 16-unit cleanup or allocation assumptions. `ProgramBuilder.addDynamicSampler` must attach the supplied binding to the current linked program after active uniform discovery, because postprocess-only samplers such as `iris_centerDepthSmooth` are added after `ProgramBuilder` construction.
- `noisetex` is owned by `CustomTextureManager`: `texture.noise` wins, otherwise the port creates a deterministic `Random(0)` fallback texture using `noiseTextureResolution` and the 1.16.5 x-major pixel order.
- Stage custom texture overrides for exact render-target aliases stop applying after the target has been flipped at least once in that stage. The alias deactivation is case-sensitive like 1.16.5: exact `colortexN` and exact legacy aliases deactivate, while differently cased sampler keys keep their shader-pack spelling. Later passes must sample the live render target, not stale custom texture data.
- Stage/global custom texture sampler keys must keep shader-pack casing. Complementary's `customTexture.textureAtlas` is intentionally preserved as `textureAtlas`; lowercasing it breaks case-sensitive GL uniform lookup after active sampler discovery.
- `shadowcomp` sources remain discoverable, but generic `ShaderLoader` does not compile them and the 1.12 pipeline does not run a `shadowCompositeRenderer`. The inspected local 1.16.5 pipeline only discovers `shadowcomp` sources and texture stages. Complementary uses `shadowcomp.csh` for colored-lighting profiles, so executable support for that would need an explicit target-pack-support divergence rather than a source-parity claim.

- Texture format metadata now follows the local 1.16.5 `TextureFormatLoader` / `StandardMacros` surface for defines: `TextureFormatLoader` reads `minecraft:optifine/texture.properties`, recognizes `lab-pbr`, clears when the file disappears, reloads the active shader pack when the format changes, clears cached PBR holders, and lets `StandardMacros` emit `MC_TEXTURE_FORMAT_*` / version defines. - The 1.16.5 final pass order is: dispatch final computes, issue memory barrier, generate requested mipmaps, render final quad or baseline copy, reset render-target mipmap filters, copy flipped alternates back to main with framebuffer `bind()`, then bind the main framebuffer, clear uniforms/samplers/program, and unbind every reported sampler texture unit. The 1.16.5 baseline-copy helper does not clear the active GL program early and the swap-copy loop does not immediately bind texture `0` after those copies; the 1.12 final renderer is expected to preserve that cleanup shape.
- Postprocess raster and compute samplers are owned by `ProgramBuilder` / `ProgramSamplers`; do not reintroduce manual render-target texture binding in final/composite passes unless the exact 1.16.5 path and 1.12 runtime evidence require it.
- `centerDepthSmooth` is no longer a CPU float uniform in postprocess programs. Postprocess sources that declare `uniform float centerDepthSmooth;` are transformed into `uniform sampler2D iris_centerDepthSmooth;` plus `texture2D(iris_centerDepthSmooth, vec2(0.5)).r`, matching the 1.16.5 `CompositeDepthTransformer` path. Keep this transform scoped to `prepare*`, `deferred*`, `composite*`, `final*`, and `shadowcomp*`; `gbuffers_*` and root `shadow` sources use the 1.16.5 attribute/world path and must not receive the postprocess sampler transform without new evidence. `CenterDepthSampler` owns the 1x1 smoothed color texture pair, copies into the alternate texture through `OculusRenderSystem.copyTexSubImage2D(...)` like the 1.16.5 non-DSA `DepthCopyStrategy` fallback, and exposes that alternate texture through the sampler. Do not switch this back to `builder.uniforms().addFloat("centerDepthSmooth", ...)`.

Do not deduplicate an existing pack-provided directive here; the inspected reference injects without checking for one. Keep this scoped to postprocess program names unless exact reference evidence proves a broader transform.

Use the unified `OpenGlHelper.GL_FRAMEBUFFER` target for active copy paths; do not reintroduce split read/draw framebuffer binds without backend-specific runtime proof.
