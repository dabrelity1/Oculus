# Architecture Map

Last updated: 2026-05-17.

This file gives future agents a map of the current 1.12.2 port. Source code remains authoritative.

## Load Flow

1. `Oculus` loads `OculusConfig` from `config/oculus.properties` during the Forge client lifecycle.
2. `OculusClientEvents` calls `ShaderPackReloader.applyConfiguredShaderPack()` on the first client tick where `Minecraft.gameDir` exists. This converts persisted `shadersEnabled`, `selectedPackName`, and option overrides into the active `PipelineManager` pack, matching the 1.16.5 `Iris.loadShaderpack()` role.
3. `ShaderPackLoader` locates the pack under `shaderpacks`, resolves the shader root, builds an `IncludeGraph`, discovers options, preprocesses `shaders.properties` from that shader root, and creates `ShaderPack`.
4. `ShaderProperties` parses `shaders.properties`.
5. `PackDirectives`, `PackRenderTargetDirectives`, and `PackShadowDirectives` convert parsed properties and const directives into runtime settings.
6. `ProgramSet` reads program sources and compute sources, applies disabled-program rules, and scans const directives.
7. `ShaderWorldRenderingPipeline` owns runtime render targets, shader programs, post passes, shadows, and per-frame phase state. It also applies directive-backed uniform configuration such as `GameplayUniforms.configure(directives)` and `ShadowUniforms.configure(directives)` when the pipeline is constructed.

`OculusConfig` alone does not activate shaders. If config says shaders are enabled but the selected pack has not been applied through `ShaderPackReloader`, `PipelineManager` will keep producing `FixedFunctionWorldRenderingPipeline`. Reload and toggle keybinds also go through `ShaderPackReloader`; disabling or failing to load a pack applies `ShaderPack.internal()` so stale external packs do not survive.

`OculusRuntimeValidation` is a dev-only branch inside the same client tick event. It is inert unless explicit JVM properties are present. With `oculus.validation.autoJoinWorld`, it waits for the main menu, resolves the named save with `ISaveFormat`, refuses version-warning worlds, verifies `canLoadWorld(...)`, and enters through Forge's `FMLClientHandler.tryLoadExistingWorld(...)`. With `oculus.validation.exitAfterWorldTicks`, it requests client shutdown after the configured number of in-world client ticks. With `oculus.validation.pbrTextures`, the real simple PBR loader, atlas PBR upload path, and `PBRTextureManager` holder resolution path emit one-time telemetry for loaded normal/specular textures. `build.gradle` forwards all three validation properties into the launched Minecraft JVM for `runClient`.

## Mixin Bootstrap

`OculusMixinLoader` is both the Forge coremod entry point and the MixinBooter early mixin loader. The jar manifest declares it with `FMLCorePlugin`, `FMLCorePluginContainsFMLMod`, and `ForceLoadAsMod`; the class implements `IFMLLoadingPlugin` and `IEarlyMixinLoader` and returns only `oculus.mixins.json`.

Do not move Oculus mixin registration back into `Oculus.onConstruction(...)`, `-Dmixin.configs`, `@MixinLoader`, or `ILateMixinLoader`. A local `runClient` crash proved that late registration reaches `BlockStateContainer$StateImplementation` too late for `BlockStateAmbientOcclusionMixin`. The current early path matches the installed Relictium/MixinBooter pattern and is covered by `OculusMixinLoaderTest`.

## Shader Pack Loading

Important classes:

- `ShaderPackLoader`
- `ShaderPack`
- `ShaderProperties`
- `ProgramSet`
- `ProgramSource`
- `ComputeSource`
- `ShaderPackOptions`, `OptionSet`, `ProfileSet`
- `PropertiesPreprocessor`, `JcppProcessor`

Key behavior:

- `shaders.properties` is preprocessed in two passes: the first pass discovers `iris.features.optional` / `iris.features.required`, then supported optional `IRIS_FEATURE_*` defines are added before preprocessing the original source again. This is required for Complementary-style metadata guarded by self-declared feature flags such as `IRIS_FEATURE_BLOCK_EMISSION_ATTRIBUTE`. Feature lists preserve the 1.16.5 token boundary: split only on spaces, preserve case and duplicates, and validate/emit names case-sensitively.
- Folder shaderpacks use a direct `<pack>/shaders` child as the shader root, matching `Iris.loadExternalShaderpack(...)` constructing `ShaderPack` from `shaderPackRoot.resolve("shaders")`. A pack-level `<pack>/shaders.properties` is not part of that root and must be ignored when the `shaders/` child exists.
- Other properties files are preprocessed with option values and the current environment defines before parsing.
- `StandardMacros` reports `MC_VERSION` as the Forge 1.12.2 target value `11202` by default, matching the 1.16.5 reference rule that the macro is the running Minecraft version. Do not clamp it to `11605`; shaderpacks use this value to choose legacy block/entity/source branches. The `oculus.mcVersionOverride` system property is only for deliberate debugging. GL vendor/renderer macros follow the local 1.16.5 prefix table, including distinct ATI vendor reporting and NVS-as-Quadro renderer reporting.
- `program.*.enabled` is evaluated during pack load and produces a disabled program set. The condition value follows the inspected 1.16.5 rule: exact `true`, exact `false`, otherwise one boolean option name. `ProgramSet` applies those keys with the same path-derived semantics as the 1.16.5 source provider: root sources use keys such as `shadowcomp`, while dimension-folder sources use keys such as `world0/shadowcomp`; compute `.csh` sources follow the same rule.
- Dimension-specific shader roots follow the 1.16.5 loader's two-step model. `dimension.properties` is preprocessed with environment defines only, not shader option values. `dimension.properties` or implicit `world0` / `world-1` / `world1` folders build a dimension map, the base root uses only the wildcard mapping when one exists, and a folder is override-capable only if `ShaderPackSourceNames.findPresentSources(...)` sees a known program start in that folder. `ShaderPack.getProgramSet(dimension)` does not apply wildcard mapping a second time; wildcard-only mappings return the cached base set for unmapped dimensions. An empty declared folder falls back to the base `ProgramSet` rather than shadowing it.
- Dimension folders are handled by `ShaderPack.getProgramSet(dimension)`.
- Source preprocessing is performed before shader compilation, not when files are first collected. `JcppProcessor` mirrors the local 1.16.5 GLSL preprocessing hack: it converts `#version` and `#extension` to internal JCPP warning markers, lets conditionals decide which directives survive, then hoists surviving directives back to the top through `GlslCollectingListener`. Environment macros are registered with `Preprocessor.addMacro(...)`; do not replace this with literal source insertion without new reference evidence.
- Legacy compatibility aliases are injected with the environment defines. `projectionMatrix` and `modelViewMatrix` map to the gbuffer matrix uniforms, `vaPosition` maps to `gl_Vertex.xyz`, and `vaNormal` maps to `gl_Normal`; this keeps Complementary's fallback line-rendering source type-correct on 1.12.

## Render Pipeline

Important classes:

- `PipelineManager`
- `WorldRenderingPipeline`
- `ShaderWorldRenderingPipeline`
- `FixedFunctionWorldRenderingPipeline`
- `GbufferPrograms`
- `WorldRenderingPhase`, `RenderCondition`, `InputAvailability`, `SpecialCondition`

The 1.12 render loop is intercepted mostly through `LevelRendererMixin`, which targets `EntityRenderer`. That mixin handles:

- frame begin/end
- shadow rendering before terrain setup
- post-camera uniform refresh from the existing `RenderGlobal.setupTerrain(...)` redirect, after vanilla `setupCameraTransform(...)` and `ActiveRenderInfo.updateRenderInfo(...)`
- main-pass frustum override for `frustum.culling=false`
- main-pass chunk visibility override for `occlusion.culling=false`
- particle ordering redirects
- weather and hand phases
- `rain.depth` depth-mask override around the 1.12 weather render call

`WorldRendererMixin` handles `RenderGlobal` phase tracking for sky, clouds, terrain layers, entities, block entities, destroy overlays, outlines, and world border. It also applies `backFace.*` terrain layer directives around `renderBlockLayer`; it skips that cull override during shadow rendering because the shadow renderer already disables back-face culling for the shadow pass. Shader-pack `sun` and `moon` toggles suppress the sliced vanilla sky draws by clearing the active sky `BufferBuilder` before the matching `Tessellator.draw()` calls. `sunPathRotation` applies to the live vanilla sky by inserting the shader-pack Z-axis tilt between vanilla's `rotateY(-90)` setup and the celestial-angle X rotation. Shader-pack cloud, vignette, and underwater-overlay toggles live in narrower vanilla hooks: `GameSettingsCloudsMixin`, `GuiIngameOverlayMixin`, and `ItemRendererOverlayMixin`.

Other render phase context comes from entity/block-entity/render-manager mixins.

`BlockRenderingSettings` stores block-rendering directives that must affect chunk rebuilds. `ShaderWorldRenderingPipeline` applies shader-pack values such as `ambientOcclusionLevel`, `separateAo`, old lighting, extended vertex format, `block.properties` block-state ID maps, and `block.properties` `layer.*` render-layer overrides; `FixedFunctionWorldRenderingPipeline` resets them to vanilla values or clears them. The block-state ID map is intentionally preserved even when it is empty, matching the 1.16.5 non-null map semantics where unmapped states emit `-1` rather than falling back to vanilla `Block.BLOCK_STATE_IDS`. `BlockContextHolder` lazily builds the vanilla fallback map only when a vanilla holder is actually requested, avoiding early empty-registry snapshots. `BlockStateAmbientOcclusionMixin` applies the AO level at the 1.12 block-state ambient occlusion brightness query. `BlockRenderLayerOverrideMixin` applies shader-pack render-layer overrides through Forge 1.12's `Block.canRenderInLayer(IBlockState, BlockRenderLayer)` hook; its `canRenderInLayer` injection is intentionally `remap = false` because Forge adds that method outside MCP `stable_39`, while `getRenderLayer` remaps normally to `func_180664_k`.

`FixedFunctionWorldRenderingPipeline.beginLevelRendering()` also follows the local 1.16.5 fallback contract: it rebinds the Minecraft main framebuffer and unbinds the active GL program before vanilla fixed-function rendering continues. Keep this path intact for shader disable, failed-pack fallback, and reload recovery work.

The shader pipeline's vanilla fallback booleans mirror the local 1.16.5 `DeferredWorldRenderingPipeline`: vanilla entity shadows are disabled only when an active `ShadowRenderer` exists, and directional shading is disabled when `oldLighting` is false. The forced shadow render-distance display uses the reference integer chunk rounding `((int) (distance * mul) + 15) / 16`, including the negative multiplier sentinel path.

`separateAo=true` currently uses vanilla and Relictium paths. `AmbientOcclusionFaceMixin`, `BlockModelRendererSeparateAoMixin`, `SeparateAoTracker`, and `BufferBuilderExtendedVertexFormatMixin` carry smooth and flat block-model AO/diffuse lighting into vertex color alpha. `BlockFluidRendererBlockContextMixin` captures the exact `BlockColors.colorMultiplier` tint for the active fluid render, while `FluidSeparateAoTracker` and `BufferBuilderExtendedVertexFormatMixin` classify completed fluid quads by normal plus true bottom-plane detection and move the vanilla fluid factors (`1.0`, `0.5`, `0.8`, `0.6`) into alpha. Relictium terrain uses `RelictiumBlockRendererSeparateAoMixin`, `RelictiumFluidRendererSeparateAoMixin`, and `RelictiumSeparateAoColor` to redirect the same `ColorABGR.mul(color, ao)` points used by the Oculus 1.16.5 Sodium mixins. Relictium terrain phase is scoped from the actual `BlockRenderPass` through `OculusTerrainPass`, so solid, cutout, cutout-mipped, and translucent chunk backend rendering can expose the matching `WorldRenderingPhase` even though the vanilla terrain-layer hooks are bypassed.

Pipeline shutdown and resize/rebuild paths clear cached g-buffer framebuffer wrappers before destroying `RenderTargets`, because those wrappers point at `GlFramebuffer` handles owned by the render-target manager. This keeps the explicit ownership order consistent even though `GlResource` also guards repeat destroys.

Composite and final postprocess framebuffers created by `RenderTargets` are returned through `RenderTargets.destroyFramebuffer(...)` during recalculation or teardown. This keeps the render-target owned framebuffer list accurate during resize/reload cycles.

Gbuffer draw-buffer state is also owned by `RenderTargets`. `ShaderWorldRenderingPipeline.bindGbufferFramebuffer(...)` gets or creates the framebuffer through `RenderTargets.createGbufferFramebuffer(...)`, binds it, and sets viewport/depth-clear state without reissuing `glDrawBuffers(...)` or `noDrawBuffers()`. That matches the local 1.16.5 `DeferredWorldRenderingPipeline.Pass.use()` path, where `createGbufferFramebuffer(...)` constructs the framebuffer draw-buffer routing and pass use only binds the selected framebuffer before viewport/program/state work.

If the shader pipeline reaches the gbuffer bind path without compiled programs, it uses the same Minecraft-main-framebuffer helper as render-target preparation cleanup instead of binding raw framebuffer `0`. This keeps the 1.12 shader-pipeline fallback boundary aligned with the local 1.16.5 fixed-function `Minecraft.getInstance().getMainRenderTarget().bindWrite(true)` contract when FBOs are enabled.

## Render Targets And Post Passes

Important classes:

- `FramebufferManager`
- `RenderTargets`
- `DepthTexture`
- `ClearPassCreator`, `ClearPass`
- `CompositeRenderer`
- `FinalPassRenderer`
- `BufferFlipper`
- `CenterDepthSampler`
- `ColorSpaceConverter`, `ColorSpaceComputeConverter`, `ColorSpaceFragmentConverter`

The pipeline distinguishes read buffers from write buffers through flipped-buffer sets. `ShaderWorldRenderingPipeline.beginLevelRendering()` fires the shared `FrameUpdateNotifier` after shader programs have registered non-camera smoothed built-in listeners and before render-target clears, mirroring the local 1.16.5 `updateNotifier.onNewFrame()` before `prepareRenderTargets()` boundary. It keeps `renderStage` at `NONE` through that notifier and render-target preparation, then switches to `SKY` afterward like the reference `setPhase(WorldRenderingPhase.SKY)` boundary. Finalization also clears `renderStage` / override phase and marks fullscreen postprocess scope before center-depth, composite, final, and color-space work so fullscreen postprocess uniforms do not inherit the last world phase and world gbuffer programs cannot resync during postprocess. Render-target preparation clears now also preserve the local 1.16.5 state boundary: `clearRenderTargets()` restores the default texture unit before clearing and rebinds the Minecraft main framebuffer in a `finally` cleanup after the clear block. `ProgramBuilder` carries that notifier through world/shadow programs, composite/final passes, shadow compute, and Relictium terrain wrappers for `wetness`, `rainStrengthS`, `rainStrengthShiningStars`, `rainStrengthS2`, `rainFactor`, and `frameTimeSmooth`; camera-dependent smoothing remains on the post-camera setup path. Final pass output targets the Minecraft framebuffer texture. Depth snapshots are used to expose the expected `depthtex*` semantics. `CenterDepthSampler` follows the 1.16.5 postprocess contract by rendering a 1x1 smoothed color texture pair from the current depth texture; postprocess shader sources that declare legacy `uniform float centerDepthSmooth;` are transformed to sample `iris_centerDepthSmooth`. Its OpenGL 3.2 precision branch goes through `OculusRenderSystem.supportsOpenGL32()` so the active postprocess path does not own a separate raw LWJGL capability probe. Its 1x1 copy path uses `OculusRenderSystem.copyTexSubImage2D(...)`, matching the local 1.16.5 `DepthCopyStrategy` non-DSA fallback and keeping 2D texture binding restoration inside the render-system helper. After sampling, it rebinds the 1.12 Minecraft main framebuffer with `bindFramebuffer(true)`, matching the 1.16.5 `mainRenderTarget.bindWrite(true)` boundary and viewport reset instead of restoring an arbitrary previous framebuffer. Postprocess raster and compute programs rely on `ProgramBuilder` / `ProgramSamplers` for render-target, shadow, custom, noise, and center-depth sampler bindings; the final path does not perform a separate manual render-target texture-unit binding pass. Composite compute dispatch uses the active Minecraft main framebuffer dimensions when available, matching the 1.16.5 renderer's dispatch inputs. Composite and final constructors clear the framebuffer binding after creating their pass/swap framebuffers; this maps the 1.16.5 read-framebuffer cleanup to the 1.12-compatible `OpenGlHelper.GL_FRAMEBUFFER` target. Composite cleanup rebinds the actual 1.12 Minecraft framebuffer with `bindFramebuffer(true)` instead of assuming framebuffer `0` is the active main target. `FramebufferVersionMixin` adds the local 1.16.5-style color/depth buffer version bridge to 1.12 `Framebuffer.deleteFramebuffer()`, and `FinalPassRenderer` uses that color-buffer version with the texture id before deciding whether its `colorHolder` attachment is still current. `FullScreenQuadRenderer` owns matrix setup, fixed-function color reset, and depth-test toggling only; callers own depth-mask, blend, alpha, and framebuffer state. `FinalPassRenderer` enters fullscreen scope before final compute dispatch on the raster path, ignores final draw-buffer and viewport-scale directives like the local 1.16.5 renderer, and follows the 1.16.5 final cleanup ordering: after final raster output or baseline copy, it resets render-target mipmap filters, copies flipped alternate buffers back to their main textures through swap framebuffers bound with `bind()` without an immediate texture-0 unbind, rebinds the main Minecraft framebuffer, clears active uniforms/samplers/program state, and unbinds every reported sampler texture unit without forcing legacy depth/blend/alpha state back on.

Postprocess renderers use `ShaderSourcePreparer.prepareProgram(...)` as the single source-preparation boundary. That shared path applies environment defines, postprocess composite compatibility transforms such as `centerDepthSmooth` and GLSL 120 `texture*Lod`, and grouped cross-stage patching before `ProgramBuilder` sees the source. Do not add renderer-local blanket `in` / `out` text rewrites after preparation; that duplicates the transform boundary and can break geometry-stage source.

Render-target depth snapshot copies preserve the 1.16.5 binding boundary for the 1.12 bind-to-edit GL path: the first dirty allocation branch binds the destination through `GlStateManager`, leaves that destination bound after `OculusRenderSystem.copyTexImage2D(...)`, and later refreshes use `OculusRenderSystem.copyTexSubImage2D(...)` to save and restore the previous `GL_TEXTURE_BINDING_2D`.

Render-target and depth texture allocation now uses the same wrapper boundary as postprocess mipmap/reset work. `OculusRenderSystem.texImage2D(...)` binds 2D textures through `GlStateManager`, performs the upload, and records texture metadata; `RenderTarget`, `DepthTexture`, and the private framebuffer-manager depth texture use it with `OculusRenderSystem.texParameteri(...)` instead of raw 2D bind/upload/filter calls.

Present composite/final raster and compute shader creation failures propagate during postprocess construction, matching the local 1.16.5 behavior. Only an absent valid final raster source enters the baseline-copy path.

Explicit postprocess render-target references also fail fast. Composite draw-buffer sizing, composite resize sizing, composite/final mipmap setup, final swap-pass creation, final swap-pass resize, and final render-target mipmap reset require configured `colortexN` targets and throw when one is missing. Missing draw-buffer directives default to `{0}` in `ProgramDirectives`, but explicitly empty draw-buffer arrays are not normalized again by `CompositeRenderer`; they should fail at framebuffer creation. The remaining null-skip in this area is general sampler enumeration over configured target slots, where a sparse 1.12 target array should not create bindings for absent entries.

`shadowcomp` source discovery and texture-stage parsing remain present, but generic shader loading does not compile those sources and the pipeline does not render a `shadowcomp` pass because the inspected local 1.16.5 `DeferredWorldRenderingPipeline` does not render it. Keep that distinction visible when auditing shadow or colored-lighting behavior.

Active framebuffer-owning code must use Minecraft 1.12.2 `OpenGlHelper` for framebuffer creation, binding, texture attachment, completeness checks, and deletion. Local MCP/bytecode evidence shows 1.12 selects the runtime framebuffer backend (`BASE`, `ARB`, or `EXT`) inside `OpenGlHelper`; direct GL30 FBO calls bypass that dispatch and are guarded against by `FramebufferCompatibilityTest`. Active copy paths bind source FBOs through the unified `OpenGlHelper.GL_FRAMEBUFFER` target rather than split read/draw targets because they use `glCopyTexImage2D` / `glCopyTexSubImage2D`, not framebuffer blits. Shared framebuffer depth attachment now reads `TextureInfoCache` internal-format metadata and chooses the depth-stencil attachment for combined depth-stencil textures, matching the local 1.16.5 `GlFramebuffer` selection while keeping the 1.12 `OpenGlHelper.glFramebufferTexture2D(...)` call path.

`ProgramSet` constructs `PackDirectives` with `PackRenderTargetDirectives.BASELINE_SUPPORTED_RENDER_TARGETS`, matching the 1.16.5 baseline-allocation path. This keeps `colortex0` available even for packs that do not declare explicit render-target directives, which is required by the empty-framebuffer path that attaches `colortex0` while disabling draw buffers. The current 1.12 resize path recreates the private `FramebufferManager` depth texture first, then rebuilds `RenderTargets` in the same `ensureFramebufferDimensionsUpToDate()` call so the new render-target owner captures the new depth texture. See `docs/render-target-lifecycle.md` before changing this behavior.

Color-space conversion follows the Oculus 1.16.5 split:

- If the active shader pack declares `supportsColorCorrection=true`, the pipeline uses `NoOpColorSpaceConverter`; packs receive `COLOR_SPACE_*` defines and the `currentColorSpace` uniform and are expected to handle correction themselves.
- Otherwise the pipeline applies an Oculus-owned post-final converter to Minecraft's main framebuffer color texture. It prefers `ColorSpaceComputeConverter` when compute shaders and image units are available, and falls back to `ColorSpaceFragmentConverter` for legacy contexts. The compute converter keeps the inspected 1.16.5 dedicated dispatch shape: bind/update with `program.use()`, dispatch `width / 8` by `height / 8` workgroups directly, issue the post-dispatch barrier, and then call `ComputeProgram.unbind()`.
- The fragment fallback patches the shared `/colorSpace.csh` resource from the 1.16.5 GLSL 330 fragment path into GLSL 120 fixed-function-compatible source and renders through `FullScreenQuadRenderer`. Its vertex source is a deliberate 1.12 adapter using `gl_Vertex.xy` and `gl_MultiTexCoord0.xy`: the 1.16.5 `/colorSpace.vsh` expects `iris_Position`, `iris_UV0`, and a `projection` uniform for a `[0, 1]` fullscreen quad, while the 1.12 helper already submits clip-space positions and fixed-function UVs. Its copyback path preserves the previous `GL_TEXTURE_BINDING_2D` around the legacy `glCopyTexSubImage2D` call, matching the local 1.16.5 non-DSA copy helper's bind/restore boundary.
- The selected value is stored in `OculusConfig` as `colorSpace`, defaulting to `SRGB`.
- `ShaderPackSelectionList` exposes the 1.12 GUI selector row and saves changes immediately, matching the binding behavior of the 1.16.5 Sodium color-space option.

## Shader Program Construction

Important classes:

- `ShaderLoader`
- `ShaderPreprocessor`
- `ShaderSourcePreparer`
- `ProgramBuilder`
- `Program`
- `ProgramSamplers`
- `ProgramImages`
- `TextureBindingRegistry`
- `SamplerLimits`

`ShaderLoader` keeps the historical one-program-per-source map for general callers, but `gbuffers_*` and root shadow names now compile only their packed `InputAvailability` variants and skip the un-specialized base compile because those names are selected through availability variants. It intentionally does not collect `prepare`, `deferred`, `composite`, or `final` raster sources; those are owned by `CompositeRenderer` and `FinalPassRenderer` like the local 1.16.5 pipeline so fullscreen programs receive the postprocess reserved sampler units and render-target bindings. `ShaderWorldRenderingPipeline` resolves the current `ProgramSource` as before, then asks the loader for `getProgram(sourceName, availability)` so the linked program matches the current texture/lightmap/overlay input state. This mirrors the local 1.16.5 `ProgramTable` shape where the program id lookup only uses texture/lightmap, but the cached pass/program key includes the full availability. The same ownership applies to root `shadow`: during shadow rendering, the world pipeline sets the shadow render condition and syncs the exact `shadow` availability variant before handing control to `ShadowRenderer`; `ShadowRenderer` must not compile, bind, unbind, or destroy its own root shadow raster program. Shadow render-target reads also follow the reference prepare timing: `flippedAfterPrepare` is visible to root shadow raster programs only when `prepareBeforeShadow` is true, while shadow compute setup always reads the empty pre-shadow flip set like the inspected 1.16.5 `flippedBeforeShadow` path. For variant-scoped names, a missing availability variant now returns `null` instead of falling back to the un-specialized base program, so a failed or missing `gbuffers_*` / root-shadow variant cannot silently run source prepared for the wrong inputs; `ShaderWorldRenderingPipeline.resolveProgram(...)` turns that selected-source/missing-program state into `ProgramLoadException` with render-condition and availability context. `ShaderLoader` reports variant-aware program-object counts and emits pack/source progress plus slow compile timing split into source preparation and compile/link/bind time. Because this 1.12 port compiles generic shader programs during first world-frame setup rather than entirely inside the pipeline constructor, `PipelineManager.beginWorldRendering(...)` owns the equivalent 1.16.5 construction-failure fallback boundary: it destroys a failed shader pipeline, installs fixed-function fallback, and records a failed-pack backoff keyed by pack name plus sorted option values so the same failed pack/options do not retry every frame. On 1.12, `StateTracker.overlaySampler` is fed by the legacy entity brightness overlay texture unit (`OpenGlHelper.GL_TEXTURE2` relative to `defaultTexUnit`), and `RenderLivingBaseEntityColorMixin` publishes the vanilla `brightnessBuffer` into the existing `entityColor` uniform; neither is a proven modern overlay texture.

After a program has been resolved, `ShaderWorldRenderingPipeline.bindProgram(...)` now follows that same fail-fast boundary. Gbuffer framebuffer binding, render-state override restoration, `program.use()`, and per-program override application run without a local `RuntimeException` catch, so invalid GL/program state fails the active shader pipeline instead of logging and silently falling back to fixed-function for one pass.

Program construction binds built-in samplers, custom textures, render targets, shadow textures, images, custom uniforms, and compatibility uniforms. `ShaderSourcePreparer` now requires raster pack sources to provide an explicit numeric `#version` before define injection, matching the local 1.16.5 `TransformPatcher` parse precondition and preventing the lower vertex/geometry compatibility helper from silently synthesizing one. Compute sources intentionally keep the current compiler-path behavior because the inspected 1.16.5 compute builders do not route them through `TransformPatcher`. `ProgramSamplers` now preserves the active GL texture unit across sampler updates and sampler clearing, matching the 1.16.5 behavior that avoids disturbing RenderType setup while uniforms/samplers are refreshed. Dynamic sampler allocation is bounded by `GL_MAX_TEXTURE_IMAGE_UNITS` through `SamplerLimits`, dynamic sampler bindings are attached to the current program after active uniform discovery, and `ProgramBuilder` can reserve texture units for a program before sampler discovery. `CompositeRenderer` and `FinalPassRenderer` reserve units `1` and `2` for postprocess programs, matching the 1.16.5 `IrisSamplers.COMPOSITE_RESERVED_TEXTURE_UNITS` allocation rule, while aliases sharing the same `TextureBinding` can reuse the existing allocated unit. For `gbuffers_*` and shadow programs, `ProgramBuilder` mirrors `IrisSamplers.addLevelSamplers(...)` by keeping `tex`, `texture`, and `gtexture` external on texture unit `0`, keeping `lightmap` external on the active 1.12 lightmap unit, and reserving world units `0`, `1`, and `2` so dynamic samplers cannot collide with vanilla level bindings. Its automatic registry fallback also mirrors the non-fullscreen sampler surface: world/shadow programs do not auto-bind low render targets `colortex0` through `colortex3`, `gdepthtex` and `depthtex2` stay composite-only, and root shadow programs do not auto-bind `depthtex0` / `depthtex1` unless an explicit caller binding says otherwise. This is deliberately scoped away from postprocess programs so fullscreen sampler allocation remains render-target driven. Postprocess cleanup unbinds all reported sampler units instead of assuming 16, but on 1.12 it must use `OculusRenderSystem.unbindTexture2DFromUnits(...)`: vanilla `GlStateManager.textureState` has only 8 cached slots, so units `0..7` go through `GlStateManager` and higher shader units use raw `GL11.glBindTexture` after `OpenGlHelper.setActiveTexture(...)`. The `2026-05-17` Xvfb Complementary smoke proved this avoids the prior `ArrayIndexOutOfBoundsException: 8` crash in `CompositeRenderer.renderAll(...)`. `ComputeProgram` mirrors the 1.16.5 `allowConcurrentCompute` synchronization rule: it inserts the pre-dispatch texture/image memory barrier only when the active pipeline does not allow concurrent compute, while composite and final renderers own their inspected post-dispatch barriers; the inspected shadow target-prep and post-shadow boundaries intentionally have no renderer-level memory barrier. On LWJGL2, compute dispatch uses OpenGL 4.3 or `GL_ARB_compute_shader`, and image load/store binding, image-unit queries, and memory barriers use OpenGL 4.2, `GL_ARB_shader_image_load_store`, or `GL_EXT_shader_image_load_store` according to the active context. `atlasSize` and `gtextureSize` read texture-unit-0 dimensions through the texture-binding notifier; `atlasSize` reports the active block-atlas texture size while `gtextureSize` reports any active 2D texture size. `blendFunc` reads live GL blend state with `StateUpdateNotifiers` hooks from the 1.12 `GlStateManager` mixins. Terrain compatibility uniforms `u_ModelScale` and `u_TextureScale` use the 1.12 Relictium/Sodium-style chunk vertex scale constants. `iris_LightmapTextureMatrix` is provided through `BuiltinReplacementUniforms` for non-availability shader sources transformed away from fixed-function texture matrix state; that fallback rewrites `gl_TextureMatrix[1]` to the uniform outside comments/strings and injects the declaration when needed. Availability-specific world/shadow variants now mirror the 1.16.5 full texture-matrix-array transform shape by always injecting `iris_TextureMatrix[8]` and renaming original `gl_TextureMatrix` references to it when present; the backport sources the lightmap entry from `gl_TextureMatrix[1]` because 1.12 bytecode proves lightmap UVs and matrix state live on unit/index `1`, not modern unit/index `2`. The same patcher applies availability-specific legacy texture-coordinate rules for `gl_MultiTexCoord0/1/2`, aliasing modern lightmap coordinate `2` back to 1.12 coordinate `1` when lightmap input is present and using `vec4(240.0, 240.0, 0.0, 1.0)` for missing texture/lightmap inputs. Those availability-backed attribute transforms now mirror the 1.16.5 compatibility-profile gate: explicit core-profile vertex shaders and unprofiled GLSL versions greater than 140 throw the reference error, while core-profile non-vertex stages skip the attribute rewrites and explicit `compatibility` profile sources continue through the 1.12-adapted path. Sodium terrain `_sodium` source preparation is deliberately outside this availability branch, matching `TransformPatcher.patchSodiumTerrain(...)` where `SodiumTerrainTransformer` runs without `AttributeTransformer`; generated Sodium terrain declarations are injected directly without deduplicating pack-provided non-internal names, matching the reference `parseAndInjectNodes(...)` shape. Overlay availability follows the 1.12 `RenderLivingBase` brightness texture unit, and the legacy color is copied from vanilla's `brightnessBuffer` into `GameplayUniforms.entityColor`; declared `iris_overlay` samplers bind to that 1.12 overlay unit when available and to an owned white fallback texture otherwise, but they do not carry the fixed-function texture-env color. The source transformer adapts the 1.16.5 `entityColor` passthrough by replacing pack `uniform vec4 entityColor` with a vertex `uniform vec4 iris_entityColor`, passing `varying vec4 entityColor` across stages, and using `entityColorGS` for geometry-stage handoff. It also rewrites source-backed postprocess `centerDepthSmooth` declarations to the reference `iris_centerDepthSmooth` sampler read, injects the reference `GL_ARB_shader_texture_lod` extension for GLSL 120 postprocess programs that call `texture2DLod` or `texture3DLod` without deduplicating an existing directive, applies the reference vertex-only Sildur water `fract(worldpos.y + 0.001)` compatibility workaround, rewrites vertex-stage `gl_MultiTexCoord3` to the bound `mc_midTexCoord` attribute when the pack has not already declared `mc_midTexCoord` and the source is not core-profile, removes later duplicate top-level functions only when the canonical signature and body both match an already-seen body, removes unused non-`main` function definitions, removes `const` from function-local declarations initialized by `const` parameters, throws the reference illegal tracked-name redefinition exception during that const cleanup, and removes empty external declarations like the reference compatibility transform. The duplicate-identical cleanup is intentionally narrow: it source-backs the MakeUp 9.3e legacy `shifted_r_dither` failure while leaving same-signature different bodies for real compiler diagnostics. `ShaderSourcePreparer.prepareProgram` then applies the grouped missing/unassigned/type-mismatched cross-stage output patch across raster stages, matching the source-backed numeric same-dimension part of the 1.16.5 grouped compatibility transformer. `currentColorSpace` and `COLOR_SPACE_*` use the same enum ordinal order as Oculus 1.16.5; `currentColorSpace` reads `OculusConfig.colorSpace`. `ShadowMap.applySamplerBindings` applies per-program shadow aliases after shader linking, including the `watershadow` branch and hardware shadow sampler gating from 1.16.5. Shadow depth textures use the 1.16.5 RGBA swizzle compatibility workaround so old packs can read depth from RGB channels, and mipmapped shadow textures only switch to mipmap min filters after mipmap generation. Sampler unit collisions have been addressed in several places, but broader runtime validation is still required for complex packs.

`TextureInfoCache` backs those texture-size uniforms with source-shaped upload metadata. `GlStateManagerTextureLifecycleMixin` records level-0 `GlStateManager.glTexImage2D(..., IntBuffer)` dimensions/internal format at method tail and clears metadata on low-level `GlStateManager.deleteTexture(int)` alongside PBR holder cleanup. Because this 1.12 port also owns direct LWJGL texture upload/delete paths, those callers notify `TextureLifecycleTracker` explicitly; `TextureLifecycleTrackerSourceTest` guards the current `src/main/java` direct `GL11.glTexImage2D(...)` and `GL11.glDeleteTextures(...)` call coverage. Texture IDs without cached upload metadata still fall back to live `glGetTexLevelParameteri` queries.

## Shadow Pipeline

Important classes:

- `ShadowMap`
- `ShadowRenderer`
- `ShadowCullingCameras`
- `ShadowRenderingState`
- `PackShadowDirectives`

The shadow renderer owns a shadow framebuffer, depth/color textures, shadow compute programs, culling camera selection, terrain/entity rendering, translucent depth copy, mipmaps, per-program shadow sampler aliases, shadow depth texture swizzles, mipmap filter timing, and shadow image bindings. Root `shadow.vsh` / `shadow.fsh` raster program ownership stays with `ShaderLoader` and `ShaderWorldRenderingPipeline`, matching the 1.16.5 pass-table boundary. Shadow target preparation is also triggered by `ShaderWorldRenderingPipeline` before it syncs the root shadow raster program: the frame performs shadow depth clear, shadow compute dispatch, and shadow color clear before any `prepareBeforeShadow` pass and before `isRenderingShadow=true`. The actual legacy framebuffer operations live in `ShadowRenderer.prepareRenderTargets()` because that class owns the 1.12 shadow framebuffer and textures; `ShadowRenderer.renderShadows(...)` must not dispatch compute after the root shadow raster program has been synced. Shadow target preparation starts by restoring the default texture unit through `OculusRenderSystem.restoreDefaultActiveTexture()`, mirroring the inspected 1.16.5 `DeferredWorldRenderingPipeline.prepareRenderTargets()` `GL_TEXTURE0` reset before depth clear, shadow compute dispatch, and shadow color clears while keeping the 1.12 `GlStateManager` cache coherent. It also matches the inspected 1.16.5 barrier boundary: neither target preparation nor the immediate post-shadow path issues a renderer-level memory barrier for shadow compute/image work; `ComputeProgram.dispatch(...)` still owns the `allowConcurrentCompute=false` pre-dispatch barrier. Shadow target allocation is lazy like 1.16.5: explicit `shadow.enabled=true` forces allocation, otherwise `ShadowMap` is created only after a linked program declares shadow samplers or `shadowcolorimg*`, and explicit `shadow.enabled=false` suppresses `ShadowRenderer` even if requested target textures exist. Shadow texture setup now goes through `OculusRenderSystem.texImage2D(...)`, `texParameteri(...)`, and `texParameter(...)` for depth swizzles so the 1.12 `GlStateManager` texture cache and `TextureLifecycleTracker` metadata follow the 1.16.5 non-DSA helper boundary. In that disabled-renderer branch, `ShadowMap` still full-clears shadow color targets once and deliberately does not clear depth, matching the inspected 1.16.5 `prepareRenderTargets()` split. The shadow framebuffer is created and attached through 1.12 `OpenGlHelper` dispatch rather than direct GL30 calls, matching the same backend-selection rule as render-target framebuffers. Before shadow terrain binds the block atlas, the renderer restores the default active texture through the same `OculusRenderSystem` wrapper so 1.12 `TextureManager.bindTexture(...)` targets the default sampler even if previous compute/sampler work left another unit active. The no-translucents depth copy now uses `OculusRenderSystem.copyTexSubImage2D(...)`, matching the local 1.16.5 non-DSA `IrisRenderSystem.copyTexSubImage2D(...)` boundary that saves the previous 2D binding, binds the destination only for the copy, and restores through the cached bind path instead of leaving texture 2D unbound before translucent shadow terrain. Validation-only shadow depth readback also restores the sampled texture through `GlStateManager.bindTexture(...)`. Shadow mipmap generation runs on dedicated `GL_TEXTURE4` through `OculusRenderSystem.setActiveTextureUnit(...)`, `generateMipmaps(...)`, and `texParameteri(...)`, then restores the dedicated unit binding with `GlStateManager.bindTexture(...)` and restores the default active unit through `OculusRenderSystem.restoreDefaultActiveTexture()`. This follows the 1.16.5 renderer's dedicated-unit mipmap pass while keeping the 1.12 texture cache coherent. Because the 1.12 path directly forces depth test, depth func, and depth write state for the legacy framebuffer pass, it also restores the previous depth-test enablement, `GL_DEPTH_FUNC`, and `GL_DEPTH_WRITEMASK` during shadow cleanup.

Shadow matrix cleanup follows the local 1.16.5 `IrisRenderSystem.restoreProjectionMatrix()` contract. The 1.12 renderer pops the model-view and projection matrices it pushed for shadow rendering, then returns the active matrix mode to `GL_MODELVIEW` before restoring the rest of the GL state.

The shadow framebuffer completeness check is fatal. If the 1.12 `OpenGlHelper` backend reports anything other than `GL_FRAMEBUFFER_COMPLETE` during construction, `ShadowRenderer` unbinds framebuffer `0`, deletes the just-created shadow FBO, and throws instead of logging a warning and continuing with an invalid shadow pass. Temporary shadow color clear framebuffers follow the same boundary: after attaching the target texture and setting the draw buffer, `ShadowMap` checks completeness through `OpenGlHelper` and throws before `glClear` if the clear target is incomplete.

`ShadowRenderingState` mirrors the 1.16.5 global shadow-pass state separately from the 1.12 entity/block-entity filtering gates. `ShadowRenderer.renderShadows` marks shadows as active before shadow framebuffer work and keeps that state through terrain setup, terrain rendering, entity rendering, translucent terrain, mipmap generation, and GL restore. `PackShadowDirectives` carries the inclusion flags from `shaders.properties`: `shadowTerrain` gates solid/cutout/cutout-mipped shadow terrain, `shadowTranslucent` gates translucent shadow terrain, and `shadowEntities` / `shadowPlayer` / `shadowBlockEntities` gate entity and block-entity shadow rendering. `beginEntityFiltering` / `endEntityFiltering` only cover the `RenderGlobal.renderEntities` call so the `RenderManagerMixin` and `TileEntityRendererDispatcherMixin` can honor those entity flags without making the whole pass suppress normal entity/block-entity rendering behavior. `getShadowOrthoMatrix` keeps the Iris method name but returns a defensive copy of the current shadow render projection, which may be perspective when `shadowMapFov` / `SHADOWFOV` is present.

`ShadowUniforms` mirrors the 1.16.5 `ShadowMatrices` math and preserves the reference split between shader-visible uniforms and the GL shadow render projection. `shadowProjection` / `shadowProjectionInverse` stay orthographic from raw `shadowDistance` / `SHADOWHPL`, matching `MatrixUniforms.addShadowArrayMatrix`. The render projection loaded by `ShadowRenderer` uses `shadowMapFov` / `SHADOWFOV` when present and otherwise falls back to that same orthographic matrix. Model-view grid snapping uses `shadowIntervalSize`, skips only exact zero, and preserves Java `%` behavior for negative camera coordinates. `ShadowUniformsMatrixTest` pins these edge cases because they look suspicious but are intentional compatibility behavior.

Shadow clearing follows the 1.16.5 model closely within the current single-texture 1.12 implementation: depth is cleared every shadow frame, shadow compute programs dispatch before shadow color clears, shadow color buffers receive one mandatory full clear after allocation, and subsequent color clears honor each buffer's `shadowcolor*Clear` and `shadowcolor*ClearColor` directives. On 1.12 this target-preparation step waits until the redirected terrain-setup hook has refreshed camera-dependent uniform caches, then runs before root shadow raster sync so compute dispatch cannot leave a compute program bound for terrain rendering.

Terrain setup uses the terrain shadow camera. Entity, player, and block-entity rendering then use the same camera when `entityShadowDistanceMul` is `1.0` or negative, or a separate entity shadow camera when the value is positive. The separate camera scales `shadowDistanceRenderMul` by `entityShadowDistanceMul`, matching the 1.16.5 behavior used by packs such as Complementary. In normal/default shadow culling, negative `shadowDistanceRenderMul` values use the 1.16.5 default user shadow distance of 32 chunks until a dedicated 1.12 shadow-distance option exists; explicit shader-pack-disabled culling keeps the reference non-positive distance behavior and does not apply that fallback.

`shadow.culling` modes:

- `DEFAULT` / `ENABLED`: use vanilla 1.12 frustum, optionally intersected with `shadowDistance * shadowDistanceRenderMul`.
- `DISABLED`: use no culling, or distance-only culling if `shadowDistanceRenderMul` requests it.
- `REVERSED`: union an inner `voxelDistance` no-cull box with the outer culling behavior.

Shadow terrain setup forces 1.12 chunk occlusion traversal off while calling `RenderGlobal.setupTerrain`, matching the 1.16.5 behavior of disabling `smartCull` around the shadow pass. It also calls `RenderGlobal.setDisplayListEntitiesDirty()` immediately before shadow `setupTerrain(...)`, which is the bytecode-confirmed 1.12 equivalent of the 1.16.5 shadow renderer's pre-setup `LevelRenderer.needsUpdate()` call; the post-shadow dirty mark remains so the main camera terrain graph is rebuilt after the shadow pass. Opaque shadow terrain renders in the reference order `SOLID`, `CUTOUT`, `CUTOUT_MIPPED`, followed by `TRANSLUCENT` later in the pass when enabled. Before translucent shadow terrain, `ShadowMap.copyDepthToNoTranslucents()` copies depth into `shadowtex1` while restoring the caller's prior 2D texture binding. With Relictium active, the terrain integration also swaps to a separate shadow visibility graph and cached camera state around shadow chunk updates/draws, mirroring the local 1.16.5 Sodium shadow-map mixins.

This is not the same implementation as 1.16.5 advanced shadow culling; verify visually before treating it as parity.

Supported concepts include custom noise textures, deterministic generated fallback noise textures, stage custom textures, global custom textures, texture-format metadata defines, first-slice PBR sampler binding, image directives, render-target image bindings, shadow image bindings, and SSBO declarations. `CustomTextureManager` now owns `noisetex` like the 1.16.5 manager: `texture.noise` wins when provided, otherwise a generated `Random(0)` RGBA noise texture is allocated at `noiseTextureResolution`, filled with the reference x-major pixel order, and registered globally. Postprocess programs explicitly bind that noise supplier before stage custom overrides, so `texture.<stage>.noisetex` can still replace it. Stage custom texture overrides preserve the shader-pack sampler spelling for case-sensitive GL uniform lookup and follow the 1.16.5 `CustomTextureSamplerInterceptor` rule exactly: exact `colortexN` names and exact legacy aliases such as `gaux*` stop using the static custom texture after the matching render target has been flipped at least once in that stage, so later passes sample the live render target. Differently cased sampler keys are not treated as those deactivated aliases. Complementary's global `customTexture.textureAtlas` path is loaded as exact-case `textureAtlas` resource data for every stage. Resource custom textures ending in `_n` / `_s` strip the suffix to the base resource and return the normal/specular texture from `PBRTextureManager`, matching the 1.16.5 `CustomTextureManager` branch. `CustomImageManager` allocates `image.*` textures, registers paired sampler bindings, clears new-frame images, and sizes the legacy `glTexSubImage*` fallback clear buffer from the OpenGL client-memory pixel representation. Scalar pixel types multiply component count by component width; packed types such as `UNSIGNED_SHORT_5_6_5` and `UNSIGNED_INT_8_8_8_8` use the packed byte width directly. Accelerated custom-image clears use `OculusRenderSystem.clearTexImage(...)`, which selects OpenGL 4.4 or `GL_ARB_clear_texture` and returns false for the legacy upload fallback when unavailable. `ShaderStorageBufferManager` owns `bufferObject.*` allocations and binding; unsupported SSBO probes do not mark requested buffers initialized, so a later GL-capable call can retry instead of permanently disabling Complementary's `SSBO` path in the same JVM. SSBO buffer zeroing similarly routes accelerated clears through `OculusRenderSystem.clearBufferData(...)`, selecting OpenGL 4.3 or `GL_ARB_clear_buffer_object` before falling back to chunked `glBufferSubData`. `TextureFormatLoader` mirrors the 1.16.5 metadata path for `optifine/texture.properties`, currently recognizing `lab-pbr` and feeding `MC_TEXTURE_FORMAT_*` defines into `StandardMacros`; `PBRTextureManager` now provides default normal/specular textures, gates bind updates to the base texture unit and active world rendering, loads `_n` / `_s` companions for `SimpleTexture`, loads atlas `_n` / `_s` sprites into same-sized PBR atlas textures, updates animated PBR atlas sprites from `TextureMap.updateAnimations()`, applies LabPBR specular nearest filtering, uses LabPBR custom specular mipmap blending, emits opt-in `OculusRuntimeValidation` PBR telemetry, and clears holders on resource/texture lifecycle events. Runtime resource-pack proof for simple and atlas PBR is still missing. Hardware capability checks live in `OculusRenderSystem` and `ImageLimits`; headless tests can set `oculus.disableGlCapabilityProbes=true` so feature-define checks report unsupported capabilities without initializing LWJGL's display path. `OculusRenderSystem` also owns legacy bind-to-edit `generateMipmaps`, `texParameteri`, `texParameter`, `copyTexImage2D`, and `copyTexSubImage2D` wrappers so render-target depth snapshots, postprocess render-target mipmap/reset/baseline-copy paths, shadow setup, and shadow mipmap generation update the 1.12 `GlStateManager` cache like the 1.16.5 non-DSA fallback. `ImageLimits` keeps the reference-style positive cache, but an initial unavailable `0` probe can be replaced by a later positive GL-context probe so parser tests do not poison later image binding in the same JVM.

Texture lifecycle metadata is split from PBR holders: `TextureInfoCache` follows the 1.16.5 cache pattern for upload dimensions used by `atlasSize` and `gtextureSize`, while `PBRTextureManager` owns normal/specular companion holders. Both are notified through `TextureLifecycleTracker` from the `GlStateManagerTextureLifecycleMixin` path and from port-owned direct LWJGL texture lifecycle calls. Postprocess center-depth texture setup and the older private framebuffer-manager color/depth/noise texture cache now use the same `OculusRenderSystem.texImage2D(...)` metadata path as render targets and shadow targets; center-depth sampling copies now use the cache-aware `OculusRenderSystem.copyTexSubImage2D(...)` helper instead of a raw bind/copy block. That older private cache also follows the source-backed generated-noise shape of `noiseTextureResolution` plus a fresh `Random(0)` x-major fill, although the active shader-pack noise path remains `CustomTextureManager`.

Uniform support is broad but should be audited against the 1.16.5 reference before claiming full parity. Custom uniforms use the vendored `kroppeb.stareval` expression evaluator. The custom-expression evaluator supports scalar and vector `bool`/`int`/`float`/`vec2`/`vec3`/`vec4` directives used by Complementary and MakeUp, including optional-ID `smooth`, `fmod`, view dimensions and `u_View*` aliases, aspect ratio, vector constructors/arithmetic, component access, fixed scalar/vector built-in uniform symbols, camera split vectors, terrain scale aliases, external matrix aliases, shadow matrix aliases, celestial vectors, Iris-exclusive vectors such as `relativeEyePosition` and `lightningBoltPosition`, bare built-in vector identifiers, hardcoded fallback symbols with shaderpack directive precedence, and `gbufferProjection.1.1` matrix element access. Camera and matrix capture has a two-step frame boundary. `CapturedRenderingState.beginFrame(...)` rolls previous camera and previous matrices once at `renderWorld` head, then `LevelRendererMixin` calls `PipelineManager.afterCameraSetup(...)` from the existing `RenderGlobal.setupTerrain(...)` redirect. At that point vanilla 1.12 has already run `setupCameraTransform(...)` and `ActiveRenderInfo.updateRenderInfo(...)`, so `CameraPositionTracker` can read the actual camera through `ActiveRenderInfo.projectViewFromEntity(entity, partialTicks)`. The fallback source is `Entity.getPositionEyes(partialTicks)`. Do not move `GameplayUniforms.onFrameStart()`, `CompatibilityUniforms.onFrameStart()`, or `CustomUniforms.beginFrame()` back to `beginWorldRendering(...)`; they intentionally run after this camera refresh so non-dynamic custom uniforms and compatibility smoothers see the correct current camera state.

`CapturedRenderingState` also derives `normalMatrix` as the inverse-transpose of the current model-view matrix after each current matrix capture. `ProgramBuilder` and custom matrix expressions use that value for `iris_NormalMatrix`, matching the local 1.16.5 Sodium chunk override's `invert()` then `transpose()` upload path. Generated Sodium terrain sources consume `mat3(iris_NormalMatrix)`, so do not bind that name back to the raw model-view inverse.

`IdMapUniforms` provides held item, entity, block-entity, and current rendered item uniforms. Held item ID lookup keeps the 1.16.5 exact `item.properties` behavior first, then applies a focused 1.12 compatibility fallback for Complementary-relevant registry renames where local bytecode proves the old names: `lit_pumpkin` resolves to `jack_o_lantern`, and `magma` resolves to `magma_block`. Entity IDs come from `BlockRenderingSettings#getEntityIds()`, matching the 1.16.5 active rendering settings owner; changing that map does not require a chunk reload because entity context is rebuilt every frame. Block-entity IDs come from `BlockRenderingSettings#getBlockStateIds()`, matching the 1.16.5 block-entity render context and keeping fixed-function fallback clear semantics aligned with terrain block IDs. Entity and block-entity lookups do not use item aliases.

## Shader Transform Notes

Grouped raster interface repair recognizes the same broad numeric type surface as the local 1.16.5 `BuiltinNumericTypeSpecifier`: booleans, explicit integer widths, `double`/`dvec*`/`dmat*`, and explicit `f16`/`f32`/`f64` float vector/matrix spellings. This is unit-tested source-preparation evidence; rare numeric interface declarations still need runtime compile validation on the target GL context.

Regular raster shader source preparation requires an explicit numeric source `#version` before define injection and rejects pack-source identifiers starting with `iris_` or named `irisMain`, matching the local 1.16.5 `TransformPatcher` validation and internal-interface guard. Generated `_sodium` sources are allowed through later internal-interface preparation because `SodiumTerrainShaderTransformer` already requires an explicit numeric source `#version` and applies that guard before injecting generated `iris_*` declarations. Those generated declarations are not deduplicated against pack-provided non-internal names such as `u_ModelScale`, matching the local 1.16.5 `SodiumTerrainTransformer` direct injection path. Compute sources intentionally keep compiler-path version handling because the inspected 1.16.5 compute builders do not route them through `TransformPatcher`.

## Known Documentation Hazard

Several files and packages are copied or transformed from multiple eras of Iris/Oculus. Names may imply modern Minecraft classes even when the runtime target is Forge 1.12.2. Always verify actual imports and mixin targets.
