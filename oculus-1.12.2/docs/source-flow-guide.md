# Source Flow Guide

Last updated: 2026-05-19.

This guide is for agents who need to trace behavior through the current Forge 1.12.2 port without getting lost in copied modern names or partially migrated systems. It complements `repo-map.md` and `subsystem-index.md`: those files tell you where code lives; this file tells you how the important flows move through the code.

Source code is still authoritative. If this guide disagrees with source, inspect the source and update this guide conservatively.

## Read This Before Tracing A Feature

- Start in `src/main/java/net/oculus`. That is the active port.
- Use `../Oculus-1.16.5` as the behavior reference before changing any rendering, shader-pack, uniform, sampler, or resource code.
- Use `run/shaderpacks/ComplementaryReimagined_r5.6.1` as the main real-world pack target, and `run/shaderpacks/MakeUp-UltraFast-9.3e` for custom-expression edge cases and secondary loader coverage. Keep both packaged copies covered when they exist.
- The current property audit for those two packs shows that normal OptiFine/Iris-style families are covered by explicit owners: profiles, screens, sliders, program gating, alpha/blend/per-buffer blend, `size.buffer.*`, texture/noise/custom texture directives, `image.*`, `bufferObject.*`, custom uniforms/variables, particles, sky/cloud booleans, and shadow render flags. Treat `dhShadow.enabled`, `dhClouds`, and `voxelizeLightBlocks` as modern target-pack observations, not 1.16.5 source-backed directives, unless a later reference source proves otherwise.
- Treat `com.mojang.*`, in-project `net.coderbot.iris.*`, and extra mixin JSON resources as compatibility or historical areas until call sites prove otherwise. Read `legacy-shims-and-remnants.md` first.
- Compile/test evidence is not runtime parity. Rendering changes need a client-world run with a real shader pack before they can be called production confidence.
- Material-ID aliases must stay exact. The current target-pack audit maps modern names only when Forge 1.12 has a matching registry/state surface, such as `cut_sandstone` to `sandstone:type=smooth_sandstone`; modern-only variants without a distinguishable 1.12 state should stay unmapped until runtime evidence proves a deliberate fallback is needed.

## Shader Pack Selection And Reload Flow

The normal selected-pack path is:

1. `OculusConfig` stores the selected shader pack, changed option values, color-space setting, user shadow render distance, and reference-compatible update-message suppression flag. Per-pack option override keys are serialized as `option.<canonical pack name>.<option id>`; the loader splits them at the last dot because current target pack names such as `ComplementaryReimagined_r5.6.1.zip` contain dots, while shader option identifiers such as `SHADOW_QUALITY` are GLSL-style names. Invalid persisted `colorSpace` or `maxShadowRenderDistance` values reset both settings to `SRGB` and `32` before rewriting the config, matching the local 1.16.5 paired recovery block while still accepting recognized 1.12 aliases such as `display-p3`. `disableUpdateMessage` is loaded only from exact `true` and saved back for persisted config parity; no active 1.12 update-message display path has been proven.
2. `OculusClientEvents` bridges persisted config into runtime state. On the first client tick where `Minecraft.gameDir` exists, it calls `ShaderPackReloader.applyConfiguredShaderPack()` so the saved enabled flag and selected pack become the active `PipelineManager` pack before world rendering needs a pipeline.
3. `ShaderPackLoader` locates the pack under `run/shaderpacks`, opens directory or zip roots, resolves `shaders/`, loads id maps, language files, options, profiles, and `shaders.properties`.
4. `ShaderPack` owns the loaded pack roots, properties, id maps, option values, and dimension-specific program sets.
5. `PipelineManager` swaps the active pack and constructs either `ShaderWorldRenderingPipeline` or `FixedFunctionWorldRenderingPipeline`. Shader-pack block-state ID maps are handed to `BlockRenderingSettings` unchanged; do not collapse an empty map to `null`, because the 1.16.5 path treats an empty non-null map as "all unmapped block IDs are `-1`".
6. `ShaderWorldRenderingPipeline` builds render targets, shadows, custom textures/images, programs, composite/final passes, and color-space conversion.

Language has three 1.12-specific bridges. `LanguageMap` loads immediate shader-pack `shaders/lang/*.lang` files and normalizes legacy names such as `en_US.lang` to `en_us`. `ShaderPackLanguageLookup` handles configured-language lookup plus `en_us` fallback. `ClientLocaleLanguageMixin` sideloads active-pack keys into `net.minecraft.client.resources.Locale`, which backs `I18n.hasKey(...)` and `I18n.format(...)`; `TextLanguageMapMixin` sideloads the same active-pack keys into `net.minecraft.util.text.translation.LanguageMap`, which backs `TextComponentTranslation`. Both shader-pack hooks check vanilla storage first and do not override existing Minecraft/resource-pack translations. Separately, `ClientLocaleLanguageMixin` runs `IrisLanguageJsonLoader` after vanilla `.lang` loading so the bundled modern `assets/iris/lang/*.json` resources are usable in 1.12. The 1.12 GUI's own English messages are carried in both `assets/oculus/lang/en_us.lang` and `assets/iris/lang/en_us.json`; `InternalTranslationResourceTest` guards those source-literal keys so missing reset/import/export/apply/profile messages fail in unit tests. `GuiUtil` still uses the shader-pack helper directly when rendering a selected pack that is not necessarily the active pipeline pack.

Current terminology trap: `ShaderPack.internal()` is the no-external-pack internal sentinel used when no shader pack is selected or when callers need a null-object pack. It is intentionally named as internal state, not as a placeholder implementation of shader-pack behavior.

Current lifecycle trap: config load alone is not pipeline activation. `Oculus.initializeConfig()` only reads `oculus.properties`; `ShaderPackReloader.applyConfiguredShaderPack()` is the active 1.12.2 replacement for the 1.16.5 `Iris.onRenderSystemInit()` / `loadShaderpack()` path. Disabled config, missing selection, missing shaderpacks directory, and load failure all deliberately apply `ShaderPack.internal()` so stale external packs cannot survive a disable or failed startup load. When that fallback pipeline begins a frame, it must rebind `Minecraft.getFramebuffer()` and unbind the active GL program, matching the local 1.16.5 fixed-function fallback state boundary. Runtime shader compilation failures can occur during the first world frame in this 1.12 port; `PipelineManager` catches shader-pipeline failures there, isolates failed shader-pipeline cleanup, installs fixed-function fallback even if texture reset or destroy cleanup fails, and records a failed-pack backoff keyed by pack name plus sorted option values. The same pack/options will not retry every frame; selecting a different pack/profile/options produces a new key for a deliberate retry.

PBR sampler usage is a selected-pack lifecycle flag in this port, not a per-dimension constructor flag. `PipelineManager.reloadShaderPack(...)` resets `PBRTextureManager` sampler usage only after the next pack's derived terrain state can be built and before `activePack` is published. `ProgramBuilder` marks usage later when linked programs declare `normals` or `specular`. Do not move that reset back into `ShaderWorldRenderingPipeline`: multiple dimension pipelines can coexist, and a dimension whose programs do not declare PBR samplers must not clear refresh state for another loaded dimension that does.

Texture-manager resource reload has a separate PBR reset boundary. `TextureFormatLoader.reload(resourceManager)` remains the owner for texture-format metadata refresh and PBR holder clearing, but `TextureManagerPBRReloadMixin` must still call the active pipeline's `resetPbrTextureBindings()` after that attempt even when metadata reload throws. The original reload failure is preserved, with reset failure suppressed onto it. This keeps active `normals` / `specular` and custom-resource `_n` / `_s` sampler suppliers from being left on deleted companion IDs solely because optional metadata reload failed first.

Inside `TextureFormatLoader.reload(...)`, new texture-format metadata is published before stale PBR holders are cleared. Holder cleanup failure must not skip the format-change shader reload: collect the `PBRTextureManager.clear()` failure, still call `onFormatChange()` when `didFormatChange` is true, then rethrow the collected cleanup failure afterward. This preserves the source-backed ordering that `MC_TEXTURE_FORMAT_*` define changes trigger shader reload pressure even when PBR cleanup reports a failure.

Keybind, GUI Apply, and resource-reload behavior follows the same rule. Public shader reload refreshes `OculusConfig` from disk like the local 1.16.5 `Iris.reload()` path, then applies the configured pack through `ShaderPackReloader.applyConfiguredShaderPack(...)`; disabled, missing, or failed configured packs deliberately fall back to `ShaderPack.internal()`. If config initialization itself fails, public reload returns `false` before applying a configured pack, preserving the current runtime state instead of rebuilding from stale in-memory selected-pack, option, color-space, or shadow-distance values after disk config refresh failed. After a successful reload decision, public reload prepares the loaded-world pipeline when a world exists, matching the inspected 1.16.5 `Iris.reload()` tail. `ShaderPackScreen.applyChanges()` prevalidates the pending selected pack, saves the pending selected pack, enabled flag, and option overrides first, then calls `ShaderPackReloader.reload()` instead of directly reloading `PipelineManager` from GUI state. When the screen opens with an invalid stored pack, `preloadSelectedPack(...)` snapshots config before clearing that pack and its overrides, and restores the snapshot plus screen selection if saving the cleanup fails, so source state does not pretend disk recovery succeeded. Main-screen Escape falls through to the normal close path, so `onGuiClosed()` applies pending changes like the reference; only the Cancel button sets `dropChanges` and discards pending state. Toggle key handling now saves the new enabled flag and calls `ShaderPackReloader.reload()` too, matching the inspected 1.16.5 `toggleShaders(...)` save-then-reload path and avoiding the startup-only apply helper after runtime state changes. The max-shadow-distance slider is not pending Apply state: like the reference video option, it writes `OculusConfig.maxShadowRenderDistance` immediately, tracks drag updates until mouse release, skips duplicate config writes for unchanged values, displays a forced pipeline shadow distance when present, and disables edits while that forced value is active. A package-visible fallback can still reload the already active external pack when no config object is available for tests or unusual startup states.

For unattended validation, `OculusClientEvents` also calls `OculusRuntimeValidation` after startup config application. This helper is inert unless validation JVM properties are present. With `oculus.validation.autoJoinWorld`, it resolves a save through `ISaveFormat`, refuses version-warning worlds, and enters the world through Forge's `FMLClientHandler.tryLoadExistingWorld(...)`; `oculus.validation.exitAfterWorldTicks` can request a clean shutdown after world entry. With `oculus.validation.pbrTextures`, the simple PBR loader, atlas PBR upload path, and `PBRTextureManager` holder resolution path log real loaded texture IDs. This is a dev-run hook, not normal gameplay behavior.

Folder shaderpacks are loaded from a direct `<pack>/shaders` child, matching the local 1.16.5 folder load path. A directory with root-level `shaders.properties` but no `shaders/` child is rejected rather than treated as a shader root, and a root-level `shaders.properties` beside a valid `shaders/` folder is ignored because the reference constructs `ShaderPack` from the shader root. Packaged shaderpacks are expected to work through the same flow as extracted directories. Root-level `shaders/` archives and nested `TopFolder/shaders` archives both follow the local 1.16.5 `Iris.loadExternalZipShaderpack(...)` lookup rule. Dimension routing also follows the local 1.16.5 split: `dimension.properties` is preprocessed with environment defines only, before shader option values and optional feature defines exist; the base `ProgramSet` root comes from the parsed wildcard dimension mapping when one exists; and a dimension folder is override-capable only after `ShaderPackSourceNames.findPresentSources(...)` finds a known program start in that folder. The include/option graph is seeded from the same known root and usable-dimension program starts, then follows `#include` edges; it no longer starts from every `.vsh` / `.fsh` / `.gsh` / `.csh` / `.glsl` file under `shaders/`, so unreferenced target-pack files such as Complementary and MakeUp `dh_*` sources do not create Iris/Oculus shader options or source-provider entries by accident. The wildcard mapping is only a base-root selector: `ShaderPack.getProgramSet(dimension)` creates a separate override only when the requested dimension has an explicit mapped folder, otherwise it returns the cached base set. `ShaderPackLoaderComplementaryTest` loads the local Complementary directory/zip and the local MakeUp directory/zip when present, builds a synthetic nested zip to prove metadata and program sources are read from the nested shader root after the loader closes its temporary zip filesystem, guards that included files still contribute options while unreferenced shader-like files do not, and prepares MakeUp runtime program sources across vanilla dimension roots plus fallback base root. That guard is headless source-preparation evidence, not a replacement for live GL compile or rendered-output validation.

## Pack Metadata To Runtime Flow

Most shader-pack metadata follows this shape:

1. Raw files are read by `ShaderPackLoader`, `IdMap`, `LanguageMap`, `ShaderProperties`, and option/preprocessor helpers.
2. `PropertiesPreprocessor` applies shader option values and environment defines before parsed runtime properties become structured values in `ShaderProperties`. Shader option discovery itself follows the local 1.16.5 `OptionAnnotatedSource` gate: boolean candidates, including valid `const bool` configurable directive names, are exposed only when their name appears in the connected-component `#ifdef` / `#ifndef` reference set, while string options bypass that boolean-only gate. Duplicate option declarations also use the 1.16.5 merge boundary: same-name conflicting defaults remove the option as ambiguous, while same-default duplicates prefer the first declaration with a comment. Changed option values store only known non-default values; unknown keys are ignored, invalid boolean text collapses to the default, and unknown boolean lookups default to `true`. Source edits use raw changed-value accessors like the reference: unchanged `const` and string lines are preserved, changed string `#define` options are replaced with the canonical `OptionAnnotatedSource: Changed option` line, `const` edits only touch the text after `=`, and boolean `#define` toggles use the reference tri-state comment helper. The default-off boolean define double-comment result is intentional source parity, not a cleanup target. For `shaders.properties`, `ShaderPackLoader` uses the two-pass `preprocessShaderProperties(...)` path: pass one discovers `iris.features.*`, supported optional feature flags are converted to `IRIS_FEATURE_*` defines, then the original source is preprocessed again so same-file metadata guards like Complementary's `IRIS_FEATURE_BLOCK_EMISSION_ATTRIBUTE` branch are visible. Feature lists themselves use the local 1.16.5 `value.split(" +")` boundary, preserve case and duplicates, and are case-sensitive when validated/emitted; do not normalize them to uppercase before `IrisFeatureDefines`. Like the local 1.16.5 `ShaderProperties`, the 1.12 port then parses behavioral directives from that processed content but parses `screen`, `screen.*`, `profile.*`, and `sliders` from the original non-preprocessed file so option-menu layout is not changed by preprocessor guards. Those layout list values intentionally split with `value.split(" +")`, not `\\s+`, because the reference only treats spaces as separators. The `screen.<name>.columns` affixed-int helper intentionally rejects an empty `<name>` and lets malformed `screen..columns` fall through to the general `screen.` list parser, matching the reference. `OptionMenuElementScreen` returns raw parsed column counts like the reference; the legacy 1.12 widget constructor clamps later for layout safety. Profile parsing also follows the local 1.16.5 behavior: assignment tokens for options not present in the discovered boolean/string `OptionSet` are recorded but ignored when matching a profile, every `!option` token is stored as `option=false`, `=` is preferred over `:`, missing or recursive `profile.*` dependencies throw, and malformed assignment sides are preserved rather than filtered.
3. Runtime-facing directive objects are built through `PackDirectives`, `PackRenderTargetDirectives`, `PackShadowDirectives`, and `ProgramDirectives`. Keep malformed-token boundaries source-backed: for example, `size.buffer.*` uses the local 1.16.5 literal-space split and rejects tab-separated or repeated-space values instead of normalizing them. Pass directives preserve empty suffixes like the reference helper. The shared two-argument helper for `texture.*` and `flip.*` also mirrors the reference: missing the second dot throws through substring bounds, and empty second arguments are passed through.
4. `ProgramSet` discovers source files and compute sources, applies disabled-program rules, and records directives per program. Disabled-program condition values follow the inspected 1.16.5 single-token rule: exact `true`, exact `false`, otherwise one boolean option name; an unknown option name defaults to enabled through `OptionValues`. The parser extracts the program key with the same first-dot rule as the 1.16.5 helper, so `program.world0/shadow.enabled` becomes `world0/shadow` and malformed extra suffixes do not become part of the key. Lookup mirrors the 1.16.5 source-provider key derived from the requested path: `/shadowcomp.fsh` maps to `shadowcomp`, while `/world0/shadowcomp.fsh` and `/world0/shadowcomp.csh` map to `world0/shadowcomp`. Empty or metadata-only dimension folders intentionally fall back to the base set instead of masking it with an empty override, and wildcard-only dimension mappings reuse the base set instead of creating per-dimension duplicate overrides. `gbuffers_damagedblock` fallback happens only after directive collection, and the fallback source receives an overridden draw-buffer list `{0}`; do not move that fallback into `readProgramSource(...)`.
5. Runtime owners consume the resolved data:
   - render targets and clears: `RenderTargets`, `ClearPassCreator`, `CompositeRenderer`, `FinalPassRenderer`
   - shadows: `ShadowMap`, `ShadowRenderer`, `ShadowSamplerBindings`
   - textures and images: `CustomTextureManager`, `CustomImageManager`, `ProgramImages`
   - samplers and uniforms: `ProgramBuilder`, `ProgramSamplers`, `ProgramUniforms`
   - terrain state: `BlockRenderingSettings`, `BlockContextHolder`, vertex-format, AO, material-ID, render-layer, and chunk-local block-position mixins for `at_midBlock`

Render-target sampler and image binding is intentionally fail-fast for active declarations that exceed the current render-target count. `IrisSamplers.addRenderTargetSamplerBindings(...)` binds configured targets, preserves the non-fullscreen skip for low `colortex0..3`, then checks active `colortexN`, legacy aliases, `oculus_rtN`, and `oculus_flipped_rtN` through `IrisLimits.MAX_COLOR_BUFFERS`. `IrisImages.addRenderTargetImages(...)` does the same for `colorimgN`. Keep this boundary if render-target count logic changes: a declared but unconfigured target should fail during program binding rather than become a silent missing sampler/image.

Special-effect built-ins (`relativeEyePosition` and `lightningBoltPosition`) are normal uniform/custom-expression value sources, not shader-pack directives. Their suppliers intentionally resolve `Minecraft.getMinecraft()` at use time like the 1.16.5 reference use-site calls, then return zero vectors when no live client/world/camera/lightning state is available. This keeps early class loading from freezing those runtime surfaces to headless zero state; live lightning and third-person camera-relative output still require client validation.

When adding support for a directive, do not stop at parsing. Update `directive-support.md` with whether the directive is implemented, parsed only, partial, missing, or unverified.

## Shader Source To Linked Program Flow

Shader source reaches GL in this order:

1. `ProgramSet` locates the pack's source files and compute files.
2. `ShaderPackLoader` builds the source include graph from `ShaderPackSourceNames.POTENTIAL_STARTS` in the root shader folder plus dimension folders that contain known program starts, then follows includes. This mirrors the local 1.16.5 `ShaderPack` constructor ordering and avoids treating unsupported or orphan shader-like files as source roots.
3. `ShaderPackLoader` resolves include text and runs `JcppProcessor.glslPreprocessSource(...)`, matching the local 1.16.5 JCPP marker path: `#version` and `#extension` are temporarily converted to internal warning markers, JCPP conditionals decide which directives survive, `GlslCollectingListener` hoists the surviving directives back to the top, and environment defines are registered through `Preprocessor.addMacro(...)` instead of being inserted into source text. Keep the macro setup failure boundary separate from source tokenization failures; `JcppProcessorTest` pins this.
4. `ShaderSourcePreparer` first requires raster pack sources to carry an explicit numeric `#version`, matching the local 1.16.5 `TransformPatcher` parse precondition, then `ShaderPreprocessor` applies includes, properties preprocessing, feature defines, legacy compatibility defines, and pack option values. Compute sources intentionally keep the current compiler-path behavior because the inspected 1.16.5 composite/final/shadow compute builders do not route them through `TransformPatcher`.
5. `ShaderCompatibilityPatcher` applies source-backed per-stage compatibility transforms such as the 1.16.5 internal `iris_` / `irisMain` pack-source guard, availability-specific `gl_MultiTexCoord0/1/2` handling, `gl_TextureMatrix` replacement, postprocess-scoped `centerDepthSmooth` to `iris_centerDepthSmooth`, GLSL 120 postprocess `texture*Lod` extension injection without deduplicating an existing directive, the 1.16.5 vertex-only Sildur water `fract(worldpos.y + 0.001)` workaround, vertex-stage `gl_MultiTexCoord3` to `mc_midTexCoord` aliasing for non-core-profile sources, duplicate-identical top-level function cleanup, unused-function removal, const-parameter declaration relaxation including the reference illegal tracked-name redefinition failure, and empty external declaration cleanup. The duplicate cleanup exists for legacy-source compatibility such as MakeUp 9.3e's active 1.12 `shifted_r_dither` duplicate: it removes only later definitions whose canonical signature and body match an already-seen body, and leaves same-signature different bodies intact so real compiler errors remain visible. Unused-function and duplicate-identical cleanup messages are debug-level diagnostics; actual compile/link failures remain error/warn-level. Non-availability callers keep the older targeted `gl_TextureMatrix[1]` to `iris_LightmapTextureMatrix` uniform fallback. Availability-specific world/shadow variants follow the local 1.16.5 `AttributeTransformer` semantics but adapt the index direction to proven 1.12 bytecode: 1.12 lightmap UVs and the lightmap texture matrix are on unit/index `1`, so lightmap-present variants alias modern `gl_MultiTexCoord2` back to `gl_MultiTexCoord1`; missing texture/lightmap variants replace unavailable fixed-function coordinates with `vec4(240.0, 240.0, 0.0, 1.0)`. Availability-backed non-core transforms always inject the replacement `iris_TextureMatrix[8]` array like the reference and rename original `gl_TextureMatrix` references to it when present, with `iris_LightmapTextureMatrix` sourced from `gl_TextureMatrix[1]` when lightmap input is present and from the 1.16.5-style dummy matrix when it is not. Generated `_sodium` sources are explicitly allowed through this later preparation step because the Sodium transform has already run the same internal-interface guard before injecting its generated `iris_*` symbols. Availability-backed attribute transforms also mirror the 1.16.5 compatibility-profile gate: `#version ... core` vertex sources and unprofiled versions greater than `140` throw the reference error, while core-profile non-vertex sources skip those attribute rewrites and explicit `compatibility` profile sources continue. Raster program preparation then runs the grouped missing/unassigned/type-mismatch cross-stage output patch across vertex, optional geometry, and fragment sources before compilation, with numeric type recognition widened to the local 1.16.5 `BuiltinNumericTypeSpecifier` surface.
6. `ShaderLoader` compiles world/shadow sources. For `gbuffers_*` and root shadow program names, it compiles one variant per `InputAvailability.NUM_VALUES` value and skips the un-specialized base program because those names are selected only through availability variants, mirroring the 1.16.5 `ProgramTable` cache shape without doing avoidable extra work. `ShaderWorldRenderingPipeline` selects the variant matching the current availability and uses the loader's variant-aware program-object count for load diagnostics. Variant-scoped lookup must return the exact variant or `null`; it must not fall back to the un-specialized base program, because that would bypass the source transforms tied to the current input state. If a concrete `ProgramSource` was selected but the exact compiled program is missing, `ShaderWorldRenderingPipeline.resolveProgram(...)` must throw instead of unbinding shaders and pretending the pass was absent. `ShaderLoader` logs pack/source progress and per-program timing with source-preparation, compile/link/bind, total time, and prepared source size so long Complementary activation has useful progress evidence without spamming one warning per cleanup. In 1.12, texture and lightmap availability come from `GlStateManager` unit enable/disable calls, and overlay availability comes from the bytecode-proven entity brightness overlay unit `OpenGlHelper.GL_TEXTURE2`; the matching legacy color is exposed through the existing `entityColor` uniform by copying `RenderLivingBase.brightnessBuffer`. Declared `iris_overlay` samplers are still provided for source compatibility, but they sample either the 1.12 white brightness texture or an owned white fallback, not the fixed-function texture-env color. Root shadow render-target reads must go through `getShadowReadBuffers()`: `flippedAfterPrepare` is valid only when `prepareBeforeShadow=true`, otherwise the pre-shadow read set is empty like the 1.16.5 `flippedBeforeShadow`. Shadow compute bindings use the empty set directly because the 1.16.5 shadow compute builder always uses `flippedBeforeShadow`. Prepare/deferred/composite/final raster sources must stay out of generic `ShaderLoader`; postprocess renderers compile them with composite reserved sampler units, render-target bindings, custom textures/images, noise, and center-depth. `shadowcomp` is discovery/directive metadata only unless a future explicit divergence re-enables it.
7. `ProgramCreator` links shaders into a GL program.
8. `ProgramBuilder` discovers active uniforms, registers built-in and custom uniforms, allocates samplers/images, reserves postprocess units, and builds `Program` or `ComputeProgram`. For `gbuffers_*` and shadow program names, OptiFine level samplers are not normal dynamic bindings: `tex`, `texture`, and `gtexture` remain external on unit `0`, `lightmap` remains external on the 1.12 lightmap unit, and world units `0`, `1`, and `2` are reserved against dynamic allocation, matching `IrisSamplers.addLevelSamplers(...)` and `WORLD_RESERVED_TEXTURE_UNITS`. Availability variants with missing texture or lightmap input bind those level samplers to the owned white fallback texture; that owner restores the previous 2D binding after setup, deletes generated IDs through a safe helper on failed setup, deletes a successfully uploaded but unpublished ID if restore fails before caching, and clears its cached ID before destroy-time delete. The automatic registry fallback is also stage-filtered: low render targets are not auto-bound in non-fullscreen world/shadow programs, `gdepthtex` and `depthtex2` stay composite-only by default, and root shadow programs skip `depthtex0` / `depthtex1`. Active `ProgramUniforms` and dynamic custom expressions attach same-frame notifiers where the 1.12 state bridge has one, including fog, object IDs, texture-size metadata, blend state, and `iris_ColorModulator` from `GlStateManager.color(...)`. Active `ProgramSamplers` detach the previous sampler set's notifier listeners, attach current listeners after the initial bind, and preserve the caller's active texture unit when a notifier callback rebinds a texture. Auto-bound `normals` and `specular` use the PBR texture-change notifiers so `ShaderWorldRenderingPipeline.onBindTexture(...)` can update those sampler texture units without requiring a full program resync.

Notifier failure aggregation is part of this runtime data flow. `FanOutValueUpdateNotifier`, `StateUpdateNotifiers` fog-toggle wrappers, `FrameUpdateNotifier`, and the combined custom-expression notifier all attempt every listener/delegate, suppress distinct later failures onto the first failure, and skip suppression when the later failure is the same throwable instance. Keep that same-instance guard when adding new notifier fan-out paths; otherwise a repeated dynamic uniform/sampler failure can be replaced by Java self-suppression before reload/fallback cleanup sees the original cause.

Important guardrails:

- `StandardMacros` owns environment macros such as `MC_VERSION`, `MC_GL_VERSION`, `MC_GLSL_VERSION`, and GL vendor/renderer macros. For this Forge 1.12.2 port, default `MC_VERSION` must remain `11202`; the 1.16.5 reference reports the running Minecraft version and does not clamp older versions upward. Unknown headless GL/GLSL probes use `000` so parser tests do not fake a Minecraft version. Vendor and renderer classification should keep the local 1.16.5 prefix table rather than collapsing ATI/NVS branches.
- `OculusRenderSystem` owns runtime capability probes and dispatch choices used by feature flags and GL extension fallbacks such as `PER_BUFFER_BLENDING`, `CUSTOM_IMAGES`, `SSBO`, center-depth OpenGL 3.2 output selection, `glClearTexImage`, and `glClearBufferData`. Headless parser tests may set `oculus.disableGlCapabilityProbes=true`; do not set it for live client/render validation because it deliberately makes those capabilities report unavailable. `ImageLimits` may cache a positive image-unit limit like the reference, but it must not permanently cache an unavailable `0` from a headless or pre-context probe. After a linked program is proven to declare an image uniform, `ProgramImages` must fail fast when the image-unit limit is zero or exhausted; silently skipping active images hides unsupported `CUSTOM_IMAGES`/compute paths. `ShaderStorageBufferManager` follows the same retry rule for requested `bufferObject.*` declarations: an unsupported probe warns but does not mark the requested buffers initialized. Its destroy path must also keep manager state cleanup in a `finally` block and log per-buffer delete failures so initialization rollback, reload, and fallback teardown cannot leave stale SSBO state behind.
- `IrisFeatureDefines` intentionally preserves the local 1.16.5 case-sensitive enum-style lookup boundary. This port supports additional uppercase feature names used by Complementary, but lowercase or tab-joined tokens should remain unsupported unless the authoritative source changes.
- Buffer-specific blend directives are the exception where the parser itself has a source-backed capability boundary. When probes are active, `ShaderProperties` throws the 1.16.5 reference error if `OculusRenderSystem.supportsBufferBlending()` is false before accepting `blend.<program>.<buffer>` metadata. Disabled-probe headless mode preserves parser coverage for packs such as Complementary without pretending that unknown GL capability is a real unsupported-platform result. Malformed blend metadata should also fail like the local 1.16.5 parser: unknown buffer names throw `Failed to parse buffer blend! index = -1`, malformed `colortex` IDs wrap the parse failure, invalid blend-mode tokens throw from `Optional.get()`, and extra valid blend-mode tokens are parsed even though only the first four are used.
- `alphaTest.<pass>` parsing follows the inspected 1.16.5 token rule: more than two space-separated tokens log a warning but still use the first function/reference pair, while fewer than two tokens are invalid.
- `TextureFormatLoader` registers with the 1.12 reloadable resource manager and feeds texture-pack format defines into `StandardMacros`. The implemented surface is `optifine/texture.properties` parsing, `lab-pbr` registry lookup, active shader-pack reload on format changes, PBR holder cache clearing, and `MC_TEXTURE_FORMAT_*` emission. `PBRTextureManager` covers the live `normals` / `specular` sampler path with base-unit and world-rendering bind gating, notifier-backed sampler rebinding, default normal/specular textures, constructor rollback if a default single-color upload fails after GL ID allocation, `SimpleTexture` `_n` / `_s` loading, successful-holder cleanup if previous texture-binding restoration fails before the holder is cached, atlas `_n` / `_s` loading for `TextureMap`, custom resource texture `_n` / `_s` indirection through the base resource, animated PBR atlas updates with nearest-previous-valid frame fallback for sparse metadata, LabPBR custom specular mipmaps, and opt-in validation telemetry for real loaded PBR texture IDs. Texture metadata and lifecycle invalidation helpers now guard same-instance suppression while restoring live query bindings and fanning out texture-delete invalidation. Runtime resource-pack proof is still missing.
- `TextureManagerPBRReloadMixin` also injects at the tail of vanilla `TextureManager.onResourceManagerReload(IResourceManager)` to reload texture-format metadata and clear PBR holders after vanilla texture reload, matching the local 1.16.5 mixin boundary. The local 1.16.5 reference also closes `PBRTextureManager` from `TextureManager.close()`; Forge 1.12 `TextureManager` has no matching close method, so `MinecraftPBRShutdownMixin` closes the PBR manager from `Minecraft.shutdownMinecraftApplet()` immediately before LWJGL `Display.destroy()`. The 1.12 port still keeps its explicit reload-listener registration path, so these hooks are source-backed lifecycle boundaries, not runtime proof of live resource-pack PBR output.
- `CustomImageManager` first asks `OculusRenderSystem.clearTexImage(...)` for the OpenGL 4.4 / `GL_ARB_clear_texture` path, then falls back to `glTexSubImage2D` / `glTexSubImage3D` when unavailable. The fallback zero buffer size must follow the OpenGL client pixel type: scalar types multiply component count by component width, but packed types use the packed element width directly.
- Source transforms must skip comments and strings unless the exact reference transform says otherwise.
- `vaPosition` must remain `gl_Vertex.xyz` for legacy compatibility; `gl_Vertex` breaks Complementary line rendering.
- Sodium terrain source transforms require an explicit numeric `#version` and reject pre-existing shaderpack `iris_*` / `irisMain` identifiers before injecting generated Relictium terrain declarations, matching the local 1.16.5 `TransformPatcher` validation and internal-interface guard. Generated declarations are then injected directly without deduplicating non-internal names such as `u_ModelScale`, matching the 1.16.5 `SodiumTerrainTransformer` `parseAndInjectNodes(...)` behavior. Regular raster shader-source preparation also requires an explicit numeric `#version` before define injection, so `ShaderPreprocessor` must not hide versionless pack sources by synthesizing one later. Regular shader-source preparation has the same internal-interface guard, but skips generated `_sodium` program names because those sources already passed the guard before generated declarations were injected. Do not replace this with duplicate-declaration suppression; generated declarations are owned by the transform.
- Sodium terrain `_sodium` source preparation must not pass `InputAvailability` into `ShaderSourcePreparer`. The local 1.16.5 `TransformPatcher.patchSodiumTerrain(...)` runs `SodiumTerrainTransformer` plus common compatibility transforms, not the separate `AttributeTransformer` branch that injects `iris_TextureMatrix[8]`.
- Do not route postprocess `tex` through the world-level external sampler rule. That rule is scoped to world/shadow programs because fullscreen stages use render-target, custom, center-depth, shadow, and noise sampler allocation instead; `shadowcomp` is part of that composite-style path, not the root shadow level-sampler path.
- For `texture.<stage>.<sampler>`, keep the inspected 1.16.5 raw-texture boundary: values with more than one space-separated token are ignored instead of treated as a filesystem path. `customTexture.*` is a separate compatibility path in this 1.12 port and should not be used as evidence to broaden `texture.*` raw parsing. Shader-pack PNG and generated `texture.noise` allocation should fail clearly if GL returns a non-positive texture ID, keep positive generated IDs under rollback cleanup until `ownedTextureIds` records ownership, and remove/delete those IDs again if previous binding restoration fails after upload but before the sampler binding is published into stage or noise state.
- Do not apply the `centerDepthSmooth` sampler transform to `gbuffers_*` or root `shadow` sources. The local 1.16.5 call graph reaches `CompositeDepthTransformer` only through `patchComposite(...)`, used by composite/final-style postprocess creation.
- Postprocess dynamic samplers such as `iris_centerDepthSmooth` must be attached after active uniform discovery.
- Compute dispatch owns pre-dispatch synchronization through `ComputeProgram`; composite/final/shadow renderers own post-dispatch barriers.

## Frame Render Flow

The 1.12 render loop is intercepted through mixins rather than a modern `LevelRenderer` pipeline:

1. `LevelRendererMixin` targets `EntityRenderer` and owns frame begin/end, post-camera uniform refresh, shadow entry, main terrain setup overrides, particles, hand, weather, and rain-depth behavior. The post-camera refresh runs from the existing `RenderGlobal.setupTerrain(...)` redirect before shadow rendering and before the redirected terrain setup call; 1.12 bytecode places this after `setupCameraTransform(...)` and `ActiveRenderInfo.updateRenderInfo(...)`.
2. `WorldRendererMixin` targets `RenderGlobal` and tracks sky, clouds, terrain layers, entities, block entities, outlines, destroy overlays, world border, and back-face directive scopes. It also owns vanilla `sun` and `moon` suppression by clearing the active sky buffer in exact sun/moon draw slices, plus the live `sunPathRotation` sky tilt before vanilla celestial-angle rotation.
3. `GameSettingsCloudsMixin` applies the shader-pack cloud override at `GameSettings.shouldRenderClouds()` while preserving the vanilla low-render-distance cloud disable.
4. `GuiIngameOverlayMixin` and `ItemRendererOverlayMixin` handle shader-pack vignette and underwater overlay toggles without changing fixed-function vanilla behavior.
5. Entity, block-entity, particle, beacon, and GL state mixins fill in narrower render-phase context.
6. `ShaderWorldRenderingPipeline` exposes phase methods and owns the current world pipeline state.
7. `GbufferPrograms`, `RenderCondition`, and `InputAvailability` choose the appropriate shader program for the current pass. Current program-id selection still ignores overlay for the id lookup like the local 1.16.5 table constructor, but compiled program variants are keyed by the full packed availability. The overlay bit can now toggle from 1.12 entity brightness state, and the existing `entityColor` uniform can receive vanilla brightness-buffer values; the modern varying `entityColor` / `iris_overlay` shader path is still an explicit remaining audit.
8. `GlStateManagerStateMixin` refreshes the active shader program before both `glDrawArrays` and `callList`. The `callList` hook matters for 1.12 entity/model rendering because `ModelRenderer#render(float)` uses display lists for normal model parts.

Mixin names can look modern even when they target 1.12 classes. Always verify imports, method descriptors, generated refmaps, and target bytecode before editing a mixin.

## Postprocess And Render Target Flow

The postprocess path uses these ownership rules:

1. `FramebufferManager` owns the private 1.12 depth framebuffer/texture used by the pipeline.
2. `RenderTargets` owns shader-pack color targets, depth snapshots, and framebuffers created for composite/final work.
3. `BufferFlipper` tracks logical main/alternate read state for color buffers.
4. `CompositeRenderer` creates deferred/composite/prepare passes, snapshots buffer read state before each pass, and applies flips after pass creation. The constructor iterates exactly the source array length like the local 1.16.5 `CompositeRenderer`; compute-only passes are only created at matching source-array indices, not for extra trailing compute-array entries, and the branch keys off non-null compute arrays rather than pre-scanning for valid compute sources. Its render cleanup still runs when the pass list is empty, matching the reference `renderAll()` cleanup boundary. Explicitly referenced draw buffers and mipmapped buffers are required; missing targets throw instead of being skipped. Missing draw-buffer directives default to `{0}` in `ProgramDirectives`, but explicitly empty draw-buffer arrays are not normalized again in `CompositeRenderer`; they should fail at framebuffer creation like the reference. `shadowcomp` sources remain discoverable metadata, but `ShaderWorldRenderingPipeline` does not create a `shadowcomp` renderer and generic `ShaderLoader` does not compile those sources because the inspected local 1.16.5 `DeferredWorldRenderingPipeline` does not render them.
5. `FinalPassRenderer` handles final compute, final raster or baseline copy, mipmap reset, alternate-to-main copy-back, main framebuffer rebind, and sampler cleanup. Its render-target mipmap/reset work and final baseline copy route through `OculusRenderSystem` / `GlStateManager` texture-state wrappers, mirroring the 1.16.5 `IrisRenderSystem` non-DSA fallback boundary. The baseline-copy helper does not clear the active GL program early; cleanup remains after mipmap reset and swap-copy work. The `colorHolder` framebuffer refresh checks the main framebuffer color texture id and the 1.12 `MinecraftFramebufferExt` color-buffer version, matching the local 1.16.5 final renderer's color attachment freshness guard. Final swap copies bind the swap framebuffer and target texture for the copy, then defer texture cleanup to the later sampler-unit unbind loop instead of immediately binding texture `0`. Final swap targets and mipmapped targets are required and fail fast when missing; only general sampler enumeration skips absent sparse entries.
6. `CenterDepthSampler` owns the 1x1 smoothed center-depth texture pair exposed as `iris_centerDepthSmooth`. The per-frame copy into the alternate texture uses `OculusRenderSystem.copyTexSubImage2D(...)`, matching the local 1.16.5 `DepthCopyStrategy` non-DSA fallback and keeping texture binding restoration inside the render-system helper.
7. `ColorSpaceConverter` runs after final output only when the active pack does not declare `supportsColorCorrection=true`.

Render-target preparation itself follows the same state boundary as the local 1.16.5 `DeferredWorldRenderingPipeline.prepareRenderTargets()`: before color clear passes, the 1.12 pipeline restores the default texture unit, and after the clear block it rebinds `Minecraft.getFramebuffer().bindFramebuffer(true)` when available. The cleanup is in a `finally` block so the main framebuffer/viewport boundary is restored even when there are no render-target clear passes. The no-program gbuffer fallback uses that same main-framebuffer helper instead of binding raw framebuffer `0`, preserving the fixed-function/main-render-target boundary when the shader pipeline reaches the gbuffer bind path before compiled programs exist. The surrounding frame phase also follows the reference: `renderStage` stays `NONE` through `FrameUpdateNotifier.onNewFrame()` and target preparation, then switches to `SKY`; finalization resets phase and override phase and marks fullscreen postprocess scope before center-depth/composite/final/color-space processing so gbuffer program sync cannot run during fullscreen passes.

Failure handling trap: do not swallow present postprocess shader failures. The local 1.16.5 `CompositeRenderer` and `FinalPassRenderer` let composite/final raster and compute creation failures abort pipeline construction. The 1.12 baseline-copy path applies only when there is no valid final raster source.

Source-transform trap: do not reintroduce renderer-local `patchCompositeShader(...)` or `patchFinalShader(...)` text rewrites after `ShaderSourcePreparer.prepareProgram(...)`. The shared preparer owns postprocess composite transforms, including `centerDepthSmooth` sampler conversion, GLSL 120 `texture*Lod` extension injection, and grouped cross-stage patching. A second blanket `in vec` / `out vec` replacement can corrupt geometry-stage sources.

Active framebuffer code must use Minecraft 1.12 `OpenGlHelper` dispatch for FBO create/bind/attach/check/delete. Do not reintroduce direct GL30 framebuffer calls in active render-target, shadow, postprocess, center-depth, or color-space paths.

Postprocess bind-to-edit texture operations are also state-cache-sensitive on 1.12. Render-target mipmap generation, mipmap filter reset, baseline copy, and swap/baseline texture binds should use `OculusRenderSystem` or `GlStateManager` so Minecraft's cached texture binding agrees with the actual GL binding.

## Shadow Flow

The shadow path starts before main terrain setup:

1. `LevelRendererMixin` enters shadow rendering through `ShaderWorldRenderingPipeline`.
2. `ShaderWorldRenderingPipeline` owns the root `shadow` raster program like the 1.16.5 pass table. It prepares shadow targets before any `prepareBeforeShadow` pass and before root shadow raster sync: `ShadowRenderer.prepareRenderTargets()` restores `OpenGlHelper.defaultTexUnit`, clears shadow depth, dispatches shadow compute, and clears shadow color targets as one block. It intentionally does not issue a target-prep or immediate post-shadow renderer-level memory barrier; `ComputeProgram.dispatch(...)` owns the `allowConcurrentCompute=false` pre-dispatch barrier. Only after target preparation does the pipeline set the shadow render condition, sync the exact `InputAvailability` variant, and call `ShadowRenderer.renderShadows(...)`. This ordering matters because dispatching compute after `syncProgram()` can leave a compute program bound for shadow terrain draws, and the default texture-unit reset mirrors the inspected 1.16.5 `DeferredWorldRenderingPipeline.prepareRenderTargets()` boundary before shadow framebuffer work. `ShadowRenderer` owns the 1.12 framebuffer implementation, terrain setup, entity/block-entity rendering, translucent handling, mipmaps, and GL restore; it must not compile or bind its own root `shadow.vsh` / `shadow.fsh` program. Root shadow raster render-target reads use `flippedAfterPrepare` only when `prepareBeforeShadow=true`; shadow compute bindings always use the empty pre-shadow read set. Before shadow `RenderGlobal.setupTerrain(...)`, it calls `setDisplayListEntitiesDirty()`; MCP bytecode shows this is the 1.12 flag that forces `renderInfos` rebuild, matching the local 1.16.5 shadow renderer's pre-setup `LevelRenderer.needsUpdate()` call. Shadow terrain layer rendering follows the 1.16.5 order: solid, cutout, cutout-mipped, then translucent later in the pass. The pre-translucent depth copy into the no-translucents shadow texture uses `OculusRenderSystem.copyTexSubImage2D(...)` so the caller's previous `GL_TEXTURE_2D` binding is restored through the cache-aware helper. Shadow mipmap generation runs on a dedicated texture unit and restores active/bound texture state instead of unbinding whichever texture unit was active after shadow rendering. The final shadow cleanup restores the depth-test enablement, depth func, and depth write mask that this 1.12 path forces for the shadow framebuffer.
3. `ShadowRenderingState` exposes pass-wide shadow-active state.
4. Entity and block-entity filtering use a narrower state window around `RenderGlobal.renderEntities`.
5. `ShadowCullingCameras` chooses terrain and entity culling cameras from `shadow.culling`, `voxelDistance`, `shadowDistanceRenderMul`, `entityShadowDistanceMul`, and the persisted `OculusConfig.maxShadowRenderDistance` user setting. Normal/default culling maps negative `shadowDistanceRenderMul` to that user shadow distance, defaulting to the local 1.16.5 32 chunks. `ShadowRenderer` skips the pass when the effective reference display distance is zero, either from unforced user distance `0` or from an explicit non-negative multiplier that rounds to zero chunks. Explicit negative render multipliers and explicit shader-pack-disabled culling keep the reference branch where negative values do not use that render-skip path. `ShaderWorldRenderingPipeline.getForcedShadowRenderDistanceChunksForDisplay()` feeds the GUI slider gate, so shader-pack-forced distances are visible but not editable from the 1.12 shader screen.
6. `ShadowUniforms` exposes shader-visible shadow matrices. The render projection may honor `shadowMapFov`, but shader-visible `shadowProjection` remains orthographic from raw `shadowDistance`.
7. `ShadowSamplerBindings` first detects whether a linked program declares shadow samplers/images. `ShaderWorldRenderingPipeline` only allocates shadow targets by default when that detection fires, while `shadow.enabled=true` forces allocation. If `shadow.enabled=false` still has requested targets, `ShadowMap` full-clears shadow color once without running the renderer. Alias binding then applies the `watershadow` branch and hardware-sampler gating.

The shadow implementation has many unit-tested pieces, but runtime visual parity is still unverified. Do not treat the legacy `ICamera` culling implementation as a full 1.16.5 advanced-frustum port.

## Uniform And Custom Expression Flow

Uniform values are split by ownership:

- `CapturedRenderingState` stores per-frame captured state. `beginFrame(...)` rolls previous camera/matrix values once at frame head, while `capturePostCameraSetup(...)` refreshes current camera and current matrices after vanilla camera setup without rolling previous matrices again.
- `ShaderWorldRenderingPipeline.beginLevelRendering()` fires `FrameUpdateNotifier.onNewFrame()` after shader compilation and non-camera smoothed built-in listener registration, but before render-target clears, matching the local 1.16.5 `DeferredWorldRenderingPipeline` frame-update boundary before `prepareRenderTargets()` for the smoothed built-ins that do not need the 1.12 post-camera hook. Keep `renderStage` at `NONE` until those clears finish, then switch to `SKY`.
- `BuiltinReplacementUniforms`, `GameplayUniforms`, `WorldInfoUniforms`, `CompatibilityUniforms`, `ShadowUniforms`, `IdMapUniforms`, and related classes compute built-in values.
- `PipelineManager.reloadShaderPack(...)` publishes active shader-pack global maps before destroying old pipelines: block-state IDs, render-layer overrides, and entity IDs are installed for shader packs and cleared for fixed-function fallback. `ShaderWorldRenderingPipeline` repeats the same pack-owned state during construction and applies directive-backed uniform configuration, including `GameplayUniforms.configure(directives)` for `wetness` / `eyeBrightnessSmooth` half-lives, `ShadowUniforms.configure(directives)` for shadow matrix inputs, and `BlockRenderingSettings#setEntityIds(...)` for the active `entity.properties` map consumed by `IdMapUniforms`. The 1.12 entity resolver uses exact Forge registry keys first, then focused legacy aliases, and special-cases `EntityLightningBolt` through `EntityList.LIGHTNING_BOLT` so MakeUp-style `minecraft:lightning_bolt` maps can be reached even though lightning is a weather-effect path in 1.12.
- `ProgramBuilder` registers built-ins, compatibility fallbacks, custom uniforms, custom variables, and dynamic samplers/images for active programs.
- Compatibility fallback uniforms must follow `HardcodedCustomUniforms` name-by-name. In particular, `shadowFade` and `shdFade` are different reference formulas and `ProgramBuilder` binds them separately.
- `CustomUniformExpressionManager` evaluates `uniform.*` and `variable.*` expressions using the vendored `kroppeb.stareval` evaluator.
- `ShaderWorldRenderingPipeline.afterCameraSetup(...)` runs gameplay, compatibility, and custom uniform frame-start pre-evaluation after the refreshed camera capture, then syncs the current program. Keep this timing unless new reference and 1.12 bytecode evidence proves another camera boundary is required.
- `iris_NormalMatrix` is derived from `CapturedRenderingState.getNormalMatrix()`, which is `transpose(inverse(gbufferModelView))`, for normal Oculus programs. Relictium-wrapped chunk programs then upload `iris_ModelViewMatrix` and `iris_NormalMatrix` again from the current GL model-view matrix after Relictium restores its owned MVP/scale uniforms, matching the local 1.16.5 chunk wrapper's post-binding matrix override as closely as the 1.12 Relictium API allows.
- ProgramBuilder-visible aliases also need custom-expression coverage when shaderpack directives use them. Current coverage includes `u_ViewWidth`, `u_ViewHeight`, `u_CameraPosition`, camera split vectors, `iris_CameraTranslation`, `iris_ScreenSize`, terrain scale aliases, and the active external matrix aliases. Viewport aliases source dimensions from the Minecraft main framebuffer when it exists, not directly from `displayWidth` / `displayHeight`, so they stay aligned with the local 1.16.5 `getMainRenderTarget()` uniform source.
- `ShadowUniforms` owns `shadowModelView`, `shadowModelViewInverse`, `shadowProjection`, and `shadowProjectionInverse`; those names and the `shadowProjectionMatrix*` aliases are also exposed to custom matrix expressions.
- `CelestialUniforms` owns `sunPosition`, `moonPosition`, `shadowLightPosition`, and `upPosition`; these are registered by `ProgramBuilder` and exposed to custom expressions.
- `SpecialEffectUniforms` owns Iris-exclusive `relativeEyePosition` and `lightningBoltPosition`; those values are registered by `ProgramBuilder` and are also exposed to custom expressions. The suppliers intentionally return zero vectors when no live client exists.
- `ExponentialSmoothing`, `SmoothedFloat`, `SmoothedVec2f`, built-in `wetness` / `eyeBrightnessSmooth`, custom `smooth()`, and `CenterDepthSampler` must preserve the 1.16.5 half-life behavior, including instant convergence for zero half-life.

Current custom-expression risk: explicit `smooth([id], ...)` state is stored per expression node. Public docs require unique IDs, but local Complementary reuses IDs. Do not change this to global keyed state unless source-level evidence and a target-pack test prove the reference collision behavior.

## Terrain And Relictium Flow

Terrain work crosses vanilla 1.12 and Relictium boundaries:

1. `BlockRenderingSettings` stores pack-driven terrain state such as AO level, old lighting, separate AO, extended vertex-format enablement, and `block.properties` `layer.*` overrides.
2. Vanilla terrain mixins under `mixin/vertexformat` extend buffer formats, capture block/fluid context, and move separate-AO factors into alpha.
3. Relictium mixins under `mixin/pipeline` target installed Relictium classes and must be verified against bytecode, not guessed from modern Sodium source.
4. `OculusRelictiumBridge`, `OculusTerrainVertexType`, `OculusVertexFormats`, and `OculusChunkMeshAttributes` bind the terrain vertex format and attributes.
5. `BlockMaterialMapping` maps shader-pack block material IDs to 1.12 block states, including focused modern-to-legacy split-block aliases for Complementary. Modern color-split names such as `orange_stained_glass`, `lime_wool`, `lime_concrete`, `white_terracotta`, and `light_gray_concrete_powder` resolve to the 1.12 block plus `color` predicate, with modern `light_gray` mapped to the 1.12 `silver` color name. Modern single plants resolve to 1.12 state predicates where vanilla 1.12 stored them under shared blocks: `grass` / `short_grass` -> `tallgrass:type=tall_grass`, `fern` -> `tallgrass:type=fern`, vanilla flowers -> `yellow_flower` or `red_flower:type=*`, vanilla saplings -> `sapling:type=*`, and supported `potted_*` names -> `flower_pot:contents=*`. Bare `flower_pot` maps to `contents=empty` so it does not preempt later potted entries. Modern double-plant names such as `sunflower`, `lilac`, `tall_grass`, `large_fern`, `rose_bush`, and `peony` resolve to 1.12 `double_plant` with the matching `variant` predicate while preserving target-pack `half` predicates. Modern six-family vanilla wood names resolve to shared 1.12 wood-family state predicates for planks, logs/log2, bark-style wood, leaves/leaves2, and wooden slabs; `petrified_oak_slab` resolves to the old `stone_slab:variant=wood` state, while stripped wood aliases intentionally stay unmapped because Complementary places them in plank-material rows before later real-log rows. Modern stone-family names resolve to shared 1.12 stone, stonebrick, and monster-egg state predicates. Bare legacy `stone`, `stonebrick`, and `monster_egg` containers are skipped only when split entries for that family exist, so first-match ID semantics do not preempt later variant-specific states. Modern prismarine names resolve to the 1.12 shared `prismarine` `rough`, `bricks`, and `dark` variants. Exact direct aliases now also include `nether_quartz_ore` -> `quartz_ore` and `magma_block` -> `magma`. When a pack declares color-split entries for a legacy single-block family, broad legacy container names such as `stained_glass`, `wool`, `carpet`, `concrete`, `concrete_powder`, and `stained_hardened_clay` are skipped so first-match ID semantics do not preempt the later color-specific states. `BlockEntry.parse(...)` also tolerates MakeUp 9.3e's malformed `namespace::block` modded entries, so `betterendforge::lumecorn:shape=light_middle` reaches the material map as `betterendforge:lumecorn` with its `shape` predicate instead of an empty block name. `BlockMaterialMapping` also maps parsed `layer.*` render types to 1.12 `BlockRenderLayer` overrides.

Forge 1.12 chunk rebuilds iterate every `BlockRenderLayer` and call `Block.canRenderInLayer(IBlockState, BlockRenderLayer)`. The `BlockRenderLayerOverrideMixin` hook is therefore the runtime bridge for shader-pack `layer.*` metadata; it must remain queued early through `oculus.mixins.json`. Keep the `canRenderInLayer` injection `remap = false`, because Forge adds that method outside MCP `stable_39`; `getRenderLayer` still remaps normally to `func_180664_k`.

`SodiumTerrainPipeline` now selects terrain/translucent/shadow shader-pack sources, applies the 1.16.5-style Sodium terrain source transform, prepares the transformed sources through the common shader source path, and exposes them to the Relictium override bridge. If Relictium requests a shadow terrain override while the active pipeline has no shadow source, `OculusRelictiumChunkProgramOverrides` now throws the same local 1.16.5-style `IllegalStateException` instead of returning `null` and silently falling back to Relictium's default chunk shader for that shadow pass. `SodiumTerrainPipelineTest` includes real Complementary zip source-generation guards, which protect this path from parser/preparer regressions, the previous declaration-regex backtracking bug, reversed generated declaration ordering, and declarations being hidden inside Complementary's leading block comment. The current transformer does not deduplicate generated declarations; that is intentional source parity with the local 1.16.5 direct injection path. `SodiumTerrainPipelineGlCompileTest` is an opt-in LWJGL Pbuffer compile/link guard for the generated Complementary solid, translucent, and shadow `_sodium` programs; run it with `-Doculus.tests.sodiumTerrainGl=true` only on a working display or virtual display, because the default test command skips before touching LWJGL. `OculusTerrainPass` maps the actual Relictium `BlockRenderPass` to both the terrain shader override and `WorldRenderingPhase`, so Relictium terrain no longer relies on vanilla `RenderGlobal.renderBlockLayer` phase hooks. The Relictium manager mixin preserves the normal backend `begin` / `render` / `end` order while adding Oculus scope cleanup if backend `render(...)` throws before normal `end()` or if backend `end()` itself throws. `LevelRendererMixin` invokes shadow rendering from the same `RenderGlobal.setupTerrain(...)` redirect that applies main terrain culling policy; keep it there because the older separate setup-terrain `@Inject` did not request shadow terrain layers in runtime validation. `ShadowRenderer` then marks `RenderGlobal.displayListEntitiesDirty` before the shadow setup so the 1.12 terrain graph rebuilds for the shadow camera, matching the local 1.16.5 `needsUpdate()` step, restores the default texture unit before binding the block atlas, renders shadow terrain layers in the reference solid/cutout/cutout-mipped/translucent order, and relies on `ShadowMap.copyDepthToNoTranslucents()`, `ShadowMap.generateMipmaps()`, and the final shadow renderer cleanup preserving texture/depth state around the 1.12 fallback paths. The shadow Relictium path also swaps to a separate visibility graph and cached camera state using `RelictiumChunkRenderManagerMixin`, `RelictiumSodiumWorldRendererShadowMixin`, and `OculusRelictiumSwappableChunkRenderManager`, following the local 1.16.5 Sodium shadow-map mixins. `RelictiumTerrainBridgeBytecodeTest` pins the installed Relictium bytecode shape used by the pass redirect, render-call cleanup redirect, end-call cleanup redirect, active-program swap mixins, and shadow visibility graph swap points; `ShadowRendererBytecodeTest` pins the vanilla 1.12 dirty-before-setup ordering, default texture-unit restore before block-atlas binding, shadow layer order, and depth-state restoration; `ShadowMapBytecodeTest` pins the no-translucents depth-copy texture binding restoration and shadow mipmap texture-unit isolation. Runtime validation now proves initial in-world `_sodium` override creation for shadow/solid/translucent, active-program override selection for solid/cutout-mipped/cutout/translucent main terrain, and shadow terrain layer requests plus `oculus:relictium-terrain-shadow` active-program selection. A later graph-swap attempt proved the new hooks fired but sampled all-clear shadow depth once, and reruns with the current readback path were blocked by X11 startup before world entry. This flow still is not parity-complete until rendered terrain, non-clear shadow depth output, shadow rendered output, runtime attributes, sampler/image bindings, reloads, and broader GL state cleanup are proven.

## Resource Lifetime Flow

The safest ownership model is:

- `ShaderWorldRenderingPipeline` owns the current world pipeline and tears down child resources on reload, resize, or disable.
- `FixedFunctionWorldRenderingPipeline` owns the no-shader frame boundary after disable/fallback; it rebinds the main Minecraft framebuffer and clears the active program before vanilla rendering proceeds.
- `PipelineManager.destroyPipeline()` must treat pipeline teardown as best-effort cleanup across every loaded dimension. Reset texture state and destroy each dimension pipeline independently, then clear the dimension map, active pipeline pointer, and Relictium/Sodium shader override version from a `finally` block so one failed destroy step cannot leave stale runtime state after reload or shader disable.
- `PipelineManager.preparePipeline(...)` and first-frame runtime fallback use the same isolated teardown helper for narrower replacement paths. If a cached dimension pipeline changes shader/fixed-function mode, or if `ShaderWorldRenderingPipeline.beginWorldRendering(...)` fails after delayed compile/setup, texture-state reset and old-pipeline destroy failures are logged but the replacement or fixed-function fallback is still installed and the Sodium/Relictium override version is bumped.
- `PipelineManager.runTeardownStep(...)` must preserve the original teardown failure. If reset-texture-state and pipeline-destroy cleanup report the same throwable instance during reload, replacement, or first-frame fallback, do not suppress it onto itself; distinct cleanup failures should still remain attached for diagnostics.
- Cached g-buffer framebuffer wrappers must be destroyed before `RenderTargets`.
- Framebuffers created through `RenderTargets` should be destroyed through `RenderTargets.destroyFramebuffer(...)`.
- Custom textures/images, render targets, shadow resources, center-depth textures, color-space converters, and shader programs need explicit teardown on pipeline destroy.
- Custom texture initialization failure must roll back partial manager state: `CustomTextureManager.initialize()` destroys any stage/noise bindings and owned texture IDs built before the failure, and PNG/default-noise setup deletes a generated GL texture if upload/setup fails before it reaches `ownedTextureIds`.
- Custom texture cleanup aggregation must preserve the original failure. If initialization rollback, PNG/default-noise previous-binding restoration, or noise alias unregister cleanup sees the same throwable instance twice, `CustomTextureManager` must not suppress the throwable onto itself; distinct cleanup failures still attach as suppressed context.
- Custom-image resize/allocation failure must leave no manager-local state behind: `CustomImageManager.initializeOrResize(...)` destroys any images allocated before the failure, unregisters their paired sampler aliases through owned-binding teardown, resets cached dimensions to `-1`, and rethrows. If a generated GL texture fails during setup or clear before it is stored in the manager, `allocateTexture(...)` deletes it and updates `TextureLifecycleTracker`.
- Custom-image allocation restore failure is also a pre-publication failure. If allocation and clear succeed but restoring the previous texture binding or active texture unit fails before `allocateTexture(...)` can return, the generated texture must still be deleted through the lifecycle-aware helper before the restore failure is rethrown.
- Custom-image cleanup aggregation must preserve the original failure. If allocation/clear restoration, replacement-registration rollback, frame-clear aggregation, or paired-sampler unregister cleanup sees the same throwable instance twice, `CustomImageManager` must not suppress the throwable onto itself; distinct cleanup failures still attach as suppressed context.
- PBR cleanup aggregation must preserve the original failure. If PBR texture-change notification, holder-load cleanup, default single-color restore, normal/specular atlas update, per-sprite atlas update, or atlas binding restore sees the same throwable instance twice, `PBRTextureManager`, `PBRAtlasHolder`, and `PBRAtlasTexture` must not suppress the throwable onto itself; distinct cleanup failures still attach as suppressed context.
- Texture/PBR helper cleanup aggregation must preserve the original failure. If fallback texture setup restore, texture-format parameter restore, simple PBR companion cleanup, or atlas-size query restore sees the same throwable instance twice, `FallbackTextures`, `TextureFormat`, `SimplePBRLoader`, and `AtlasPBRLoader` must not suppress the throwable onto itself; distinct cleanup failures still attach as suppressed context.
- Texture metadata and lifecycle invalidation cleanup must preserve the original failure. If live texture-size query binding restoration or texture-delete invalidation fan-out sees the same throwable instance twice, `TextureInfoCache` and `TextureLifecycleTracker` must not suppress the throwable onto itself; distinct restore/delete-notification failures still attach as suppressed context.
- Base texture bind callback aggregation must preserve the original failure. The `GlStateManager.bindTexture(...)` return hook must still attempt texture-binding notifier publish, pipeline `onBindTexture(texture)`, and final cache-restoring bind before rethrowing, but it must not suppress a throwable onto itself when one callback forwards the same failure instance; distinct callback failures still attach as suppressed context.
- Active program binding cleanup must preserve the original failure. `ProgramUniforms`, `ProgramSamplers`, `ProgramImages`, and `Program` all use guarded suppression when aggregating cleanup failures from listener detach, sampler unbind, image-unit unbind, `glUseProgram(0)`, or failed activation cleanup. If the same throwable instance is reported twice, it must stay as the original activation/reload/teardown failure; distinct cleanup failures still attach as suppressed context.
- Custom uniform expression dependencies must be classified by their upload-time source, not only by their parse shape. Captured gbuffer matrices, shadow matrices, current GL matrices, `iris_NormalMatrix`, and `iris_LightmapTextureMatrix` resolve from live per-frame state and must stay dynamic so `uniform.*` / `variable.*` expressions are evaluated at upload/use time instead of being cached during `beginFrame()`.
- Custom uniform expression managers must capture shader-pack directive state that affects built-in symbol values. `heldBlockLightValue` depends on `oldHandLight`, so it must use the properties captured when the expression manager was created, not `PipelineManager.INSTANCE.getActivePack()` at value time.
- Shader-pack held item IDs must be resolved against the compiled pack's `item.properties` map. Program builders should route `heldItemId` / `heldItemId2` through the captured custom-uniform manager state created by `CustomUniformExpressionManager.fromShaderPack(...)`; direct active-pack lookup is only a fallback for internal/helper paths without pack context.
- `currentRenderedItemId` should store render-item state, not a pre-resolved active-pack ID. The render-item mixin publishes the current `ItemStack` and the consuming uniform/custom-expression binding resolves it with the captured pack item map.
- Color-space converter cleanup follows the same suppression rule. `ColorSpaceComputeConverter` and `ColorSpaceFragmentConverter` must not suppress a throwable onto itself while cleaning compute/image state, fragment fallback setup rollback, swap-texture lifecycle notifications, process cleanup, or state restoration after a post-final conversion failure; distinct cleanup failures still attach as suppressed context.
- Relictium terrain override cleanup follows the same suppression rule. `OculusRelictiumChunkProgramOverrides`, `OculusRelictiumProgramLinker`, and `OculusRelictiumChunkProgram` must not suppress a throwable onto itself while cleaning partial rebuilds, failed wrapper creation, shader link leftovers, or non-owning wrapper deletes; distinct cleanup failures still attach as suppressed context.
- Relictium terrain scope cleanup must not let wrapped program unbind failure skip engine-scope restoration. `RelictiumChunkRenderShaderBackendMixin` clears override/pass/phase fields before cleanup can throw, handles both `RuntimeException` and `Error` from backend `begin()`, independently attempts `Program.unbind()`, pipeline lookup, `endSodiumTerrainRendering()`, previous phase restore, and previous-phase reset, then rethrows collected cleanup failures with same-throwable suppression guarded.
- PBR holder load failure must not leave accepted companion textures behind. `PBRTextureManager.loadHolder(...)` closes normal/specular textures accepted by the active loader before returning the default holder on `RuntimeException`, closes them before rethrowing `Error`, and successful or cached holders clean up through `clear()` / `onDeleteTexture(...)` without deleting default textures or deleting the same texture object twice. `closeHolder(...)` also resolves normal and specular companion textures independently so one failing holder accessor cannot skip cleanup for the reachable companion, and cleanup aggregation must not suppress a throwable onto itself.
- 2D texture bind-to-edit work in custom texture/image, fallback texture, texture-info, texture-format, and PBR paths must restore the previous `GL_TEXTURE_BINDING_2D` through `GlStateManager.bindTexture(...)`, not raw `GL11.glBindTexture(GL_TEXTURE_2D, ...)`, because Forge 1.12.2 caches only a small vanilla 2D texture-unit state array. `CustomImageManager` keeps 3D image texture binds on raw GL with separate `GL_TEXTURE_BINDING_3D` save/restore because vanilla `GlStateManager` does not cache 3D targets.
- Program sampler setup initializes active external sampler uniforms (`tex`, `texture`, `gtexture`, `lightmap`, `iris_overlay`, `u_BlockTex`, and `u_LightTex`) on externally-owned units and reserves those units in the allocator before later dynamic or custom sampler bindings are placed. Keep that reservation path intact so custom textures, PBR samplers, render-target aliases, and image-paired samplers do not silently collide with vanilla atlas/lightmap/overlay ownership.
- Program default samplers are a unit-zero contract, not a generic dynamic sampler. `ProgramSamplers.Builder.addDefaultSampler(...)` must bind active names on texture unit `0` and fail if unit `0` is reserved or already managed, matching the local 1.16.5 fullscreen/default sampler boundary.
- When a shader-pack custom texture overrides an active external unit-0 sampler, keep it on texture unit 0 like the local 1.16.5 `CustomTextureSamplerInterceptor`; nonzero external overrides still need dynamic units. If an existing sampler binding is replaced, update allocator ownership too, so later aliases that use the same `TextureBinding` can share the existing unit instead of consuming another dynamic unit.
- If a notifier-backed dynamic sampler overrides an existing active sampler, update the binding's notifier as well as the texture supplier. If the override supplies no notifier, preserve the current notifier so PBR `normals` / `specular` and other default-notifier samplers keep their rebind callbacks after custom texture/resource replacement. `ProgramSamplersTest` directly covers the single-sampler and shared-alias PBR cases.
- Window resize should rebuild the private depth framebuffer first and then rebuild render targets so new owners capture the new depth texture.

If you change lifetime behavior, update `render-target-lifecycle.md`, `architecture.md`, `backport-status.md`, and `agent-handoff.md`.

## How To Trace One Feature Safely

Use this checklist for any new feature or audit:

1. Find the active 1.12 owner in `repo-map.md` or `subsystem-index.md`.
2. Open the exact 1.16.5 reference classes.
3. Search the target shader pack for the directive, uniform, sampler, image, program, or option name.
4. Inspect 1.12 MCP/Forge/Relictium bytecode for method names, descriptors, and hook points.
5. Trace parse-time data into runtime consumers.
6. Add focused tests for pure Java parsing, source transforms, directives, uniform math, or resource bookkeeping.
7. Run the matching Gradle command and focused hygiene checks.
8. For rendering behavior, run a client-world scenario with a real pack and record logs/screenshots or observations.
9. Update the owning docs with exact evidence and remaining uncertainty.

If any step cannot be completed because exact source, bytecode, mappings, or runtime data is missing, record that blocker in `evidence-log.md` instead of guessing.

## 2026-05-19 Terrain Material Mapping Flow Note

When a modern block ID maps to multiple Forge 1.12 states, do not force it through `resolveLegacyBlockEntry(...)` if a single `BlockEntry` cannot represent the result. `quartz_pillar` is the current example: broad modern entries must claim `quartz_block:variant=lines_x`, `lines_y`, and `lines_z`, while explicit `axis=x|y|z` entries narrow to one variant. The safe flow is:

1. Detect the special multi-state alias before generic lookup.
2. Resolve/remove modern-only predicates such as `axis`.
3. Match concrete 1.12 `IBlockState` variants directly.
4. Keep source tests for both synthetic entries and real target-pack rows.

This remains source/test evidence only until in-client Relictium or fallback terrain vertices prove the shader-visible material IDs.

For modern redstone split predicates, consume predicates that choose a Forge 1.12 split registry before state matching. The current comparator example is:

1. Read `powered=true|false` on modern `comparator` entries.
2. Select `powered_comparator` or `unpowered_comparator`.
3. Remove `powered` because Forge 1.12 comparator states do not expose it as a property.
4. Keep `mode=compare|subtract` so the chosen 1.12 split block still narrows to the correct comparator mode.

`BlockMaterialMappingTest#comparatorPoweredPredicateIsConsumedBefore112StateMapping` and `ShaderPackLoaderComplementaryTest#complementaryComparatorRowsCover112SplitModes` pin the source behavior against synthetic rows and the real Complementary rows.

## 2026-05-19 Shadow Direct Binding Flow Note

Most shader-loader, postprocess, final, and Relictium terrain shadow sampler/image paths call `ShadowMap.requireShadowTargets(...)` before applying bindings. The direct `ShadowRenderer` path calls `ShadowMap.applySamplerBindings(...)` directly, so that method must keep its own active-resource guard:

1. Return only for a null builder before querying uniforms.
2. Build the `ShadowSamplerBindings.ResourceQuery`.
3. Fail on unsupported active shadow resources before creating any `TextureBinding`.
4. Return false only when no active shadow target resources exist.
5. Fail when active shadow resources exist but targets are disabled or unavailable.
6. Create and apply depth/color texture bindings only after those checks.

`ShadowMapTextureStateTest#directShadowSamplerBindingPathFailsUnsupportedResourcesBeforeBinding` pins this ordering. This is a narrow runtime data-binding guard in a shadow-owned class; it does not prove live shadow framebuffer contents or visual parity.

## 2026-05-19 Built-In Time And Hand-Light Flow Note

The built-in time uniforms are shared global state, not shader-pack-local state. `SystemTimeUniforms.COUNTER` and `SystemTimeUniforms.TIMER` feed `frameCounter`, `framemod*`, `frameTime`, and `frameTimeCounter`; keep the 720720-frame counter wrap, millisecond-resolution frame delta, and one-hour `frameTimeCounter` reset aligned with the local 1.16.5 reference.

Hand-light flow has two separate boundaries. `heldBlockLightValue` may apply `oldHandLight` to merge main/offhand light, while `heldBlockLightValue2` remains offhand-only. Direct uniforms and custom expressions should keep using the same split so reload/fallback state cannot make the offhand value inherit the main-hand directive semantics.

`SystemTimeUniformsTest` and `ProgramBuilderReferenceUniformCoverageTest` pin the source behavior. Live timer ordering and held-light values remain runtime-unverified.

## 2026-05-19 Uniform Client Lookup Flow Note

Do not store `Minecraft.getMinecraft()` in static fields inside uniform value helpers that may be loaded before the live client singleton exists. `WorldInfoUniforms`, `CompatibilityUniforms`, and `SpecialEffectUniforms` should resolve the singleton when a value is read, then null-check world, camera, or player state before producing fallback values.

This matters for both direct built-ins and custom expressions because `uniform.*` / `variable.*` evaluation may read `cloudHeight`, `ambientLight`, `isDry`, `isRainy`, `isSnowy`, `inSwamp`, `is_hurt`, `is_burning`, `sneakSmooth`, and adjacent compatibility symbols long after helper classes were loaded by headless tests, pack parsing, or early startup code.

`WorldInfoUniformsTest`, `CompatibilityUniformsTest`, and `SpecialEffectUniformsTest` pin the source behavior. Live client timing and shader-visible output remain runtime-unverified.

## 2026-05-19 Custom Resource Binding Flow Note

For `image.*` declarations, keep the image-unit path and sampler path separate:

1. Allocate custom image textures during resize/init.
2. Add an image binding only if the linked program declares the image uniform.
3. Always offer the paired sampler binding for the custom image texture, because a program may sample the custom image without declaring image access.

For custom resource PBR paths, detect `_n` / `_s` after removing only the final filename extension. Multi-dot base names must be preserved: `textures/block/stone.v2_n.png` resolves to base `textures/block/stone.v2.png`, not `textures/block/stone.png`.

`CustomImageManagerTest`, `ProgramSamplersTest`, `CustomTextureManagerTest`, and `TextureFormatLoaderTest` pin these source flows. Live image contents, sampler output, resource reload behavior, and PBR visuals remain runtime-unverified.

## 2026-05-19 SSBO Binding Flow Note

For `bufferObject.*` declarations, treat allocation and repeated pass binding as separate state boundaries:

1. Allocation may bind the generated buffer to upload and clear storage.
2. Pass refresh may bind indexed SSBO slots with `glBindBufferBase(...)` before world, composite, final, or post-compute work.
3. Both paths must restore the caller's generic `GL_SHADER_STORAGE_BUFFER` binding after successful work or failures.

`ShaderStorageBufferManagerTest#initializeRestoresPreviousGenericSsboBindingAfterAllocation` and `#bindAllRestoresPreviousGenericSsboBindingAfterIndexedBindings` pin the source order. Live driver state and shader-visible SSBO contents remain runtime-unverified.

## 2026-05-19 Startup Config Apply Flow Note

The startup configured-pack path must use the same stale-config boundary as public reload:

1. Register the texture-format reload listener first.
2. Read the global `OculusConfig`.
3. If config exists, call `reloadConfig(config)` before reading selected-pack or option override state.
4. If config refresh fails, prepare any already-loaded world pipeline fallback and return without configured-pack application.
5. Only then resolve the shaderpacks directory and call `applyConfiguredShaderPack(config, shaderpacksDirectory)`.

`ShaderPackReloaderTest#publicStartupApplyRefreshesConfigBeforeUsingConfiguredPack` pins this order. Live first-tick startup behavior and shader-visible state after config I/O failure remain runtime-unverified.
