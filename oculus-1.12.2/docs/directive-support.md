# Shader Directive Support

Last updated: 2026-05-19.

This document tracks important `shaders.properties` and const directives in the current 1.12.2 port. It is not exhaustive yet; update it when adding directive support.

Status meanings:

- Implemented: parsed and wired to runtime behavior.
- Partial: parsed and partly wired, but runtime parity is not proven.
- Parsed only: value is stored but no verified runtime effect.
- Missing: no known current support.
- Unverified: code may exist, but no focused audit has confirmed behavior.

## Runtime Binding Notes

- Active sampler/image discovery now classifies the LWJGL 2 sampler and image enum families exposed by the 1.12 runtime, including 1D, 2D, 3D, cube, array, rectangle, buffer, signed integer, unsigned integer, and multisample forms, as managed surfaces in `ProgramBuilder`. This avoids treating those active uniforms as missing built-ins, but actual non-2D sampler contents and image writes remain runtime-unverified.
- `texture.<stage>.<sampler>` stage names now keep the local 1.16.5 exact lowercase parsing boundary. `shadowcomp`, `prepare`, `gbuffers`, `deferred`, and `composite` are accepted; mixed- or upper-case stage names are ignored as unknown stages instead of being lowercased into active custom texture bindings. Runtime sampler output remains unverified.
- Texture-format parameter edits for PBR normal/specular textures now use `OculusRenderSystem.runWithoutTextureBindCallback(...)` around their temporary `GlStateManager.bindTexture(...)` calls. This keeps the 1.12 texture cache coherent while preventing LabPBR filtering setup for `normals`, `specular`, or custom resource `_n` / `_s` samplers from being reported as a fresh base-texture bind. Live callback timing and sampler output remain runtime-unverified.
- Active externally-managed sampler uniforms now reserve their texture unit in `ProgramSamplers` before dynamic/custom sampler placement. This keeps vanilla atlas, lightmap, overlay, and wrapped external units from being silently reused by later managed sampler aliases; if a distinct managed binding already owns the unit, the builder fails fast. Custom texture overrides of active external unit-0 samplers now keep the override on unit 0 like the 1.16.5 interceptor, while nonzero external overrides still move to a dynamic unit. Runtime sampler output remains unverified.
- Render-target sampler bindings for `colortexN`, legacy aliases, `oculus_rtN`, and `oculus_flipped_rtN` now re-read the current `RenderTargets` slot when the texture ID is supplied, matching the local 1.16.5 update-time lookup boundary. The helper is shared by composite/final program registration and world-pipeline sampler registry aliases. Live sampler contents, resize/reload behavior, and Relictium wrapped-program sampler output remain runtime-unverified.
- Render-target image bindings for `colorimgN` now re-read the current `RenderTargets` slot when the texture ID is supplied, matching the local 1.16.5 helper shape instead of capturing the target object at registration. Registered targets that disappear fail fast; sparse 1.12 slots are still skipped during registration. Live image contents and image-store behavior remain runtime-unverified.
- Active image-unit cleanup now covers directive-backed render-target images, shadow color images, and custom images after active-uniform discovery. `ProgramImages` unbinds stale image units when programs switch and clears active image bindings from raster program unbind/delete paths plus compute unbind, so `image.*` / render-target / shadow image state is less likely to leak across reload, fallback, or wrapper transitions at source level. Live image writes and driver cleanup behavior remain runtime-unverified.
- Composite, final, and center-depth postprocess cleanup paths now call `ProgramImages.clearActiveImages()` alongside their manual uniform/sampler cleanup. This is documented as a narrow postprocess-internal edit because those paths deliberately do not call broad `Program.unbind()` before their framebuffer/copy/swap restoration boundaries, but directive-backed image state still needs to be cleared there. Live postprocess image output remains runtime-unverified.
- The compute color-space converter now clears its target image supplier and compute program image bindings from a guarded `finally` path. This protects the image-binding state used by `supportsColorCorrection=false` compute conversion after dispatch or barrier failures at source level; live color-space output remains runtime-unverified.
