# Full-Port Parity Roadmap

Last updated: 2026-05-19.

This roadmap answers the practical question: what still separates this repository from a faithful, production-grade Forge 1.12.2 backport of Oculus 1.16.5? It is intentionally strict. A green Java build is not the finish line.

## Completion Bar

The port can only be called complete when these are all true:

- Shader-pack loading, preprocessing, options, profiles, directives, and resources match the 1.16.5 reference where 1.12.2 allows it.
- All built-in uniforms, samplers, images, buffers, and custom expressions used by real packs are registered with correct timing and values.
- World, shadow, deferred, composite, final, hand, weather, entity, block-entity, particle, terrain, and translucent passes run in the expected order.
- GL state is restored or intentionally owned across every intercepted 1.12.2 render path.
- Complementary Reimagined and at least one other serious OptiFine/Iris-style shader pack run without shader compile failures, missing bindings, framebuffer errors, or obvious visual regressions.
- Any behavior that cannot be identical because of the 1.12.2 renderer is documented with exact evidence.

## Current Answer

Yes, there is still a long way left for a full port. The foundation is no longer fake or stub-only, and many core systems are real. The latest Complementary runs are stronger than menu startup smokes because they apply the configured pack, enter a world, create `ShaderWorldRenderingPipeline`, compile the active shader pack, prove initial Relictium `_sodium` terrain override creation for shadow, solid, and translucent terrain, prove active-program override selection for solid, cutout-mipped, cutout, and translucent main terrain, and prove shadow terrain layer requests plus `oculus:relictium-terrain-shadow` active-program selection. The latest Xvfb smoke compiled 162 Complementary zip programs, completed 180 in-world client ticks, reconfirmed main/shadow terrain override selection, and fixed the texture-unit 8 postprocess cleanup crash. The 1.16.5-style Relictium shadow visibility graph swap is now implemented and bytecode-guarded, the 1.12 `RenderGlobal` shadow setup path now forces the terrain graph dirty before shadow `setupTerrain(...)` like the 1.16.5 pre-shadow `needsUpdate()` call, shadow target preparation now restores the default texture unit before shadow framebuffer work like the 1.16.5 target-prep boundary, the no-translucents shadow depth copy now routes through `OculusRenderSystem.copyTexSubImage2D(...)` so the same cache-aware copy boundary preserves the previous 2D binding before translucent shadow terrain, shadow mipmap generation now routes dedicated-unit mipmap/filter edits through cache-aware `OculusRenderSystem` wrappers with restore guards, and the legacy shadow pass restores the active matrix mode plus depth state it forces. Source parity also tightened around failure boundaries: gbuffer program bind failures, incomplete shadow framebuffers, and incomplete temporary shadow color clear framebuffers now fail the active pipeline instead of being logged, skipped, or hidden behind GL errors; vanilla entity-shadow and directional-shading booleans match the local 1.16.5 shader pipeline, and forced shadow-distance display uses the reference chunk rounding. Runtime shadow depth output is still not proven because the latest samples were all clear. Production-grade parity still depends on visual validation, non-clear shadow depth and shadow rendered-output validation, warning triage, lifecycle/reload checks, and several high-risk audits.

The largest remaining work is not just adding Java classes. It is proving that the current 1.12.2 render hooks produce the same shader-visible state and pass timing that Oculus 1.16.5 provides.
